Build the overlay half of the abstraction: a per-module registry (`createOverlays`), the handle API that drives any Radix root or the Lightbox, the single global `<AppOverlays>` mount, and the shared `<OverlayBody>` deep-link boundary.

Purpose: this is what makes "adding an overlay is one config line plus the component" true. **All commands below run in Windows PowerShell 5.1 (D-49).** No `&&`, no `grep`, no POSIX `find`, no `diff`.

- Sequence with `;`. Where the next command must only run on success: `A; if ($LASTEXITCODE -ne 0) { exit 1 }; B`.
- Search with `rg`. Use `rg -qF` / `-cF` / `-nF` whenever the pattern is literal source text — `(`, `)`, `[`, `]`, `{`, `}`, `$` are regex metacharacters, and unescaped they match the wrong thing rather than erroring.
- Alternation is `a|b`, never `a\|b` (rg reads `\|` as a literal pipe).
- `-E` is **not** extended-regex in rg, it is `--encoding`. `rg -qE` exits `2` with `unknown encoding` — which satisfies a "returns non-zero" check and becomes a silent pass. Regex is rg's default; drop the `E`.
- Write inner double quotes as `\"` — PowerShell 5.1 strips them before the argument reaches a native exe. **Exception:** a pattern that *begins* with `\"` and also contains a space is split into two argv entries, so drop the quotes and match the inner text instead.
- No POSIX `diff` — in PowerShell it aliases `Compare-Object`, which compares the two path *strings* rather than the files. Use `Compare-Object (Get-Content a) (Get-Content b)`.
- **No glob in a path argument.** PowerShell does not expand globs for native commands, so `rg -n 'X' apps/*/app/layout.tsx` hands rg a literal `*` and exits `2` (`os error 123`). Name the files, or use rg's own `--glob` flag.
- Git ranges use `master`.

**These are rules about shell syntax, never about quoted source text.** A pattern like `rg -qF 'a.id === b.id && a.desc === b.desc'` is TypeScript inside an argument and keeps its `&&`; the same goes for `;`, `|` and `$` inside a pattern.

```tsx
"use client"

import * as React from "react"
import { useSearchParams } from "next/navigation"
import { createSerializer, parseAsString, useQueryStates, type UrlKeys } from "nuqs"
import { registerQueryStateKeys } from "./key-registry"
import type {
  OverlayComponent,
  OverlayDef,
  OverlayGroup,
  OverlayHandle,
  OverlayHandles,
} from "./types"

/**
 * D-12: overlays open with `push` and close with `replace`. Browser back closes
 * an open overlay; closing via the UI does not strand a forward entry that
 * re-opens it. Both use `scroll: false` and nuqs's default shallow mode.
 *
 * D-42: nuqs's throttle queue merges every update in a ~150 ms window into one
 * history write and applies `push` if ANY contributor asked for it. An overlay
 * open coalesced with a table filter change therefore produces one `push` entry
 * capturing both — acceptable, and arguably exactly the shareable-link goal, but
 * it means D-12 and D-26 are not independently guaranteed. Do not fire an
 * overlay open and a table update from the same handler.
 */
const OPEN_OPTIONS = { history: "push", scroll: false } as const
const CLOSE_OPTIONS = { history: "replace", scroll: false } as const

/** Auto-mounted overlay whose param value is an entity id (D-31, first form). */
export function entity(
  component: OverlayComponent,
  options?: { defaultValue?: string }
): OverlayDef {
  return { component, mount: "global", defaultValue: options?.defaultValue }
}

/** Auto-mounted overlay with no payload — open/closed only (e.g. ManageTagsDialog). */
export function flag(component: OverlayComponent): OverlayDef {
  return { component, mount: "global", defaultValue: "1" }
}

/**
 * Key-only registration (D-31 second form, D-47). `<AppOverlays>` skips it; the
 * page renders the component itself and pulls its handle via `group.use(name)`.
 * Use this only when the overlay needs something that cannot cross a layout
 * boundary — today that is exactly one case, the gallery Lightbox's live
 * `originRef` handle to the clicked thumbnail (D-32). A second use is a signal
 * to revisit D-08.
 */
export function pageEntity(options?: { defaultValue?: string }): OverlayDef {
  return { mount: "page", defaultValue: options?.defaultValue }
}

/** Minimal structural shape of the base-merging `createSerializer` overload. */
type OverlaySerializer = (
  base: URLSearchParams,
  values: Record<string, string | null>
) => string

/**
 * The D-10 `href` serializer call, extracted as a pure function.
 *
 * Two reasons this is not inlined in `useGroup`:
 *   1. Testability. As a closure inside a hook it is unreachable from the
 *      node-only vitest project (D-46), and every migrated trigger in this
 *      phase calls `open()` rather than `href()` — so the one behaviour D-10
 *      exists for would ship with no test of its own code path at all.
 *   2. `base` is not optional. Passing `searchParams` is the entire point: with
 *      no base, `createSerializer` starts from an empty URLSearchParams and the
 *      link silently drops every table filter (RESEARCH §1.6, Pitfall 5). A
 *      named function with a required `base` parameter makes that unforgettable.
 *
 * `value: null` clears the key rather than setting it.
 */
export function buildOverlayHref(
  serialize: OverlaySerializer,
  searchParams: URLSearchParams,
  name: string,
  value: string | null
): string {
  return serialize(searchParams, { [name]: value })
}

/**
 * Declare a module's overlays once (D-07).
 *
 * Everything outside `useGroup` runs ONCE at module evaluation. The parser map
 * and urlKeys object are frozen and never rebuilt — requirement 2 of D-41.
 */
export function createOverlays<const C extends Record<string, OverlayDef>>(
  namespace: string,
  defs: C
): OverlayGroup<C> {
  const names = Object.keys(defs) as (keyof C & string)[]

  // Every overlay param is a plain string with NO default, so `undefined` is a
  // stable defaultValue identity and no `eq` is needed. Absent = closed (D-05).
  const parsers = Object.freeze(
    Object.fromEntries(names.map((name) => [name, parseAsString]))
  ) as Record<keyof C & string, typeof parseAsString>

  // D-13: `{namespace}.{name}`. A dot in a URL key is legal and is never parsed
  // as a path. D-29: overlay keys are ALWAYS dot-namespaced.
  const urlKeys = Object.freeze(
    Object.fromEntries(names.map((name) => [name, `${namespace}.${name}`]))
  ) as Readonly<Record<keyof C & string, string>>

  registerQueryStateKeys(namespace, Object.values(urlKeys), "overlay")

  const serialize = createSerializer(parsers, { urlKeys: urlKeys as UrlKeys<typeof parsers> })
  const defaultOf = (name: keyof C & string) => defs[name]!.defaultValue ?? "new"

  function useGroup() {
    const [values, setValues] = useQueryStates(parsers, { urlKeys, scroll: false })
    const searchParams = useSearchParams()

    // Mirror the live values so the stable actions below can read them without
    // taking a dependency on them. Same pattern as data-table-toolbar.tsx:44-45.
    const valuesRef = React.useRef(values)
    valuesRef.current = values

    // Stable across renders — depends only on nuqs's own stable setter. This is
    // what lets a memoized column factory or a useCallback close over `open`
    // without rebuilding on every URL change.
    const actions = React.useMemo(() => {
      const out = {} as Record<
        keyof C & string,
        Pick<OverlayHandle, "open" | "close" | "toggle">
      >
      for (const name of names) {
        const open = (value?: string) =>
          void setValues({ [name]: value ?? defaultOf(name) } as never, OPEN_OPTIONS)
        // Idempotent: Radix can fire onOpenChange(false) more than once (e.g.
        // Escape during an exit animation). Setting null twice is harmless but
        // still schedules a flush, so short-circuit (RESEARCH §7.3).
        const close = () => {
          if (valuesRef.current[name] === null) return
          void setValues({ [name]: null } as never, CLOSE_OPTIONS)
        }
        out[name] = {
          open,
          close,
          toggle: (value?: string) =>
            valuesRef.current[name] === null ? open(value) : close(),
        }
      }
      return out
    }, [setValues])

    return React.useMemo(() => {
      const handles = {} as OverlayHandles<C> & { closeAll: () => void }
      for (const name of names) {
        const value = values[name] ?? null
        const isOpen = value !== null
        const { open, close, toggle } = actions[name]!
        handles[name] = {
          isOpen,
          value,
          open,
          close,
          toggle,
          dialogProps: {
            open: isOpen,
            onOpenChange: (next: boolean) => (next ? open() : close()),
          },
          // Base = the CURRENT search params. Without the base, createSerializer
          // starts from an empty URLSearchParams and the link drops every table
          // filter (RESEARCH §1.6, Pitfall 5). Returns a query-only string; cast
          // to `Route` at the call site — @villuh/ui does not import next's types.
          // The serializer call itself lives in `buildOverlayHref` so it is
          // reachable from the node-only test project (D-46).
          href: (v?: string) =>
            buildOverlayHref(
              serialize as unknown as OverlaySerializer,
              searchParams,
              name,
              v ?? defaultOf(name)
            ),
        }
      }
      // One call clears exactly this group's keys and leaves other params alone.
      handles.closeAll = () => void setValues(null, CLOSE_OPTIONS)
      return handles
    }, [values, actions, searchParams, setValues])
  }

  function use<K extends keyof C & string>(name: K): OverlayHandle {
    return useGroup()[name]
  }

  return { namespace, defs, urlKeys, useGroup, use }
}
```

import * as React from "react"
import type { OverlayDef, OverlayGroup } from "./types"

type AnyOverlayGroup = OverlayGroup<Record<string, OverlayDef>>

/**
 * The single global overlay mount (D-08). Registering a module here happens
 * once; after that, adding an overlay is one line in that module's config plus
 * writing the component.
 *
 * Mount position is load-bearing (D-34):
 *   - INSIDE <UserProvider>   — ManageTagsDialog calls useUser() for its write check
 *   - OUTSIDE <PageTransition> — that is a ViewTransition keyed on pathname; an
 *                                open overlay inside it would fade or remount on
 *                                every navigation
 *
 * Every registered overlay component runs its hooks on every authenticated page,
 * so every tRPC query inside one MUST be gated on `overlay.isOpen` (D-36).
 * Gate the QUERY, never the JSX — conditionally rendering the overlay unmounts
 * the Radix root before Presence can run the exit animation (RESEARCH §7.1).
 */
export function AppOverlays({ modules }: { modules: readonly AnyOverlayGroup[] }) {
  return (
    <>
      {modules.map((group) => (
        <OverlayGroupMount key={group.namespace} group={group} />
      ))}
    </>
  )
}

/**
 * One component instance per group, so `useGroup()` is a normal top-level hook
 * call rather than a hook inside a loop. This is why AppOverlays needs no
 * eslint disable: the `modules` array may vary in length across mounts without
 * ever changing the hook sequence of any single component instance.
 */
function OverlayGroupMount({ group }: { group: AnyOverlayGroup }) {
  const handles = group.useGroup()
  return (
    <>
      {Object.entries(group.defs).map(([name, def]) => {
        // D-47: `mount: "page"` entries are registered for namespacing, the
        // collision assert, closeAll(), and href() — but rendered by their page.
        if (def.mount === "page" || !def.component) return null
        const Component = def.component
        return <Component key={name} overlay={handles[name]!} />
      })}
    </>
  )
}
```

`AppOverlays` renders no DOM of its own — it is fragments all the way down, so it composes anywhere in a layout.

Do not add `forceMount` anywhere. With the registry the Radix root is already permanently mounted, so `Presence` handles the exit animation; `forceMount` would only pin the portal contents in the DOM permanently, cost nodes, and make hidden form fields focusable.

Do not make the overlay components lazy in this phase. Shape the `OverlayDef.component` type so `component: Component | (() => Promise<{ default: Component }>)` is a non-breaking addition later, but leave lazy loading deferred per CONTEXT.

/**
 * Deep-link boundary for an overlay (D-15). Handles loading, not-found, and
 * forbidden once so no overlay reimplements them.
 *
 * Structural copy of `PageBoundary` (page.tsx:98-159), widened to discriminate
 * the tRPC error code. Keeping the query type structural is deliberate — it
 * keeps @villuh/ui free of a TanStack Query dependency.
 *
 * D-44: the FORBIDDEN branch exists for correctness and to future-proof a
 * role-gated read, but it is currently UNREACHABLE. RLS turns every
 * cross-organization read into NOT_FOUND before any authorization check runs
 * (which is also the right posture — no existence oracle). Do not write an
 * acceptance test for it; you cannot produce the state.
 */
export function OverlayBody<TData>({
  query,
  pending,
  notFound,
  forbidden,
  children,
}: {
  query: OverlayQuery<TData>
  pending: React.ReactNode
  notFound?: React.ReactNode
  forbidden?: React.ReactNode
  children: (data: TData) => React.ReactNode
}): React.ReactNode {
  if (query.isError) {
    const code = query.error?.data?.code
    if (code === "NOT_FOUND") {
      return (
        notFound ?? (
          <EmptyState
            icon="IconQuestionCircle"
            title="Not found"
            description="This record no longer exists, or the link is out of date."
          />
        )
      )
    }
    if (code === "FORBIDDEN") {
      return (
        forbidden ?? (
          <EmptyState
            icon="IconLock"
            title="No access"
            description="You don't have permission to view this."
          />
        )
      )
    }
    return (
      <EmptyState
        icon="IconWarningSign"
        title="Something went wrong"
        description={query.error?.message || "Please try again."}
      />
    )
  }

  // Mirrors PageBoundary: `data === undefined` also covers the disabled-query
  // window (a `useQuery` with `enabled: false` reports `isLoading: true` and
  // `data: undefined` in TanStack Query v5+), so content never renders without data.
  if (query.isLoading || query.data === undefined) return pending

  return children(query.data)
}
```
