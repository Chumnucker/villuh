## Accomplishments

- `parseAsFieldFilters` implements D-45's grammar exactly: a token containing `:` opens a predicate, a bare token appends a value to the open one. `status=any:s1,s2` yields one predicate with two values; `baseRent=gte:1500,lte:3000` yields two predicates with one value each.
- Unknown and field-unsupported operators are dropped rather than thrown (D-19, T-03.1-05). `bogus:1,gte:2` yields exactly the `gte` predicate; `empty` against `idFilterOperators({ nullable: false })` yields `null`; a leading continuation value, an empty query, and a valueless `gte:` all return `null` without throwing.
- **The escape scheme is bijective for the vectors that broke the original design.** `decodeValue` is one left-to-right `v.replace(/~(.)/g, …)` scan, and the suite asserts each of `a:b`, `c,d`, `e~f`, `~c`, `~s`, `~~`, `a~cb` individually. `~c`, `~s` and `a~cb` fail under the three-pass sequential decode; `.replace(` appears exactly 4 times in comment-stripped code (6 would mean the broken form returned).
- `parseAsSort` validates the column id against the table's sortable allow-list (T-03.1-06), `pageParser` is nuqs's own `parseAsIndex` rather than a hand-rolled ±1 (D-43), and `sizeParser` rejects `?size=999` via `parseAsNumberLiteral(DATA_TABLE_PAGE_SIZES)` (T-03.1-07).
- Both non-primitive parsers declare `eq` and the filter parser's default is one frozen module-scope array shared by every instance — the two conditions D-41 identifies as the actual cause of setter churn (Pitfall 1, the search box that never commits).
- `<NuqsAdapter>` is the outermost provider inside `<body>` in both apps, imported directly from `nuqs/adapters/next/app`. No `<Suspense>` wrapper, no `"use client"` added, no adapter import anywhere in `packages/ui` (D-40). Both apps build with no `missing-suspense-with-csr-bailout`.

## Decisions Made

- **The bare valueless alias is handled before the token loop, not inside it.** The plan's `<action>` block called for this ("before the token loop, if the whole `query` is exactly a valueless URL alias…") and it is worth restating why: under D-45's grammar a token without `:` is a continuation value, so `empty` can only be recognised as an operator when it is the entire param. That is also exactly the exclusivity rule D-45 states — empty / not-empty must be the only predicate on its field — so the implementation and the grammar agree rather than special-casing around each other.
- **The two `from "nuqs"` import statements in the plan sketch were merged into one.** Task 2's sketch opens with its own import block; appending it verbatim would have produced a duplicate import of `createParser` and a lint error. Purely mechanical, no behaviour change.
