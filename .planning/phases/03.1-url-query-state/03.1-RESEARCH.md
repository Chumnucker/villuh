# Phase 03.1: URL Query State (nuqs) - Research

**Researched:** 2026-08-13
**Domain:** Client-side URL search-param state management (React 19 / Next.js 16 App Router)
**Confidence:** HIGH (nuqs API verified against the published `nuqs@2.9.5` tarball source, not docs alone)

## Summary

`nuqs@2.9.5` is the right and current tool, and almost every mechanism CONTEXT.md assumes exists does exist — with better guarantees than the doc assumes. Cross-hook batching is real and global (one URL write per ~150ms window in the Next.js App Router adapter, coalescing every setter from every hook), setters are already `useCallback`-wrapped, parsed values keep referential identity while their query string is unchanged, and nuqs's URL encoder deliberately leaves `:` and `,` unescaped, so D-18's human-readable `status=any:s1,s2&baseRent=gte:1500,lte:3000` renders literally in the address bar.

Three findings change the plan materially. First, **setter referential stability is conditional, not automatic**: `useQueryStates` re-creates its setter whenever the parser map's `defaultValue` identity changes and the parser has no `eq`. A `defineTable`-generated keyMap that calls `.withDefault([])` per render will churn `setQuery` on every render and permanently break `DataTableToolbar`'s 300 ms search debounce — so D-25's `useCallback` is necessary but *not sufficient*; the parser map must be built once and every non-primitive parser must supply `eq`. Second, **`push` wins over `replace` when updates coalesce**, so an overlay open (D-12, `push`) landing in the same ~150 ms flush window as a table filter change (D-26, `replace`) produces a single `push` entry — benign, but it means the two history policies are not independently guaranteed. Third, **D-08's global overlay mount does not work for the gallery Lightbox**: it needs a live DOM ref to the clicked thumbnail for its shared-element zoom, which cannot cross a layout boundary. That one overlay must stay page-mounted with only its *state* in the URL.

The `useParams()`-from-`(app)/layout.tsx` assumption behind D-14 is verified correct at the source level — Next 16's `useParams` reads a single root-level `PathParamsContext` holding the full current-URL params, not a per-layout slice.

**Primary recommendation:** Build one `useQueryStates` call per group (overlays and tables alike) with a **module-scope, frozen parser map**, give every array/object parser an explicit `eq`, and keep the Lightbox out of the global registry.

### 1.1 `Options` — every option, exact name and default

```ts

  | { method: 'debounce'; timeMs: number }

  scroll?: boolean                    // default false
```

`[VERIFIED: dist/defs-BUTBdnWx.d.ts + dist/debounce-DPoC4s1g.js:5-27]`

Notes with plan consequences:

- `clearOnDefault: true` is the v2 default. D-20 gets a clean URL for an untouched table **for free** — but only if every parser declares a `defaultValue` *and* a correct `eq` (see §1.5).
- Throttle values below 50 ms are ignored. `+Infinity` disables URL writes entirely while keeping hook state in sync — useful in a test harness, not in app code.
- `limitUrlUpdates` takes precedence over `throttleMs` when both are set.
- Precedence for all options: **call-level > parser-level (`.withOptions()`) > hook-level (2nd arg) > `<NuqsAdapter defaultOptions>`**. `[CITED: nuqs.dev/docs/batching]` and confirmed by the destructuring at `dist/index.js:485` plus per-key resolution at `:586-592`.

### 1.3 `useQueryStates` and `urlKeys`


`[VERIFIED: dist/index.d.ts:474-494]`

Behaviours that matter for D-13:

- `urlKeys` is a plain `Partial<Record<stateKey, urlKey>>`; unmapped keys use the state key verbatim (`getUrlKey` → `getOwn(urlKeys, key) ?? key`). A dot in the URL key (`unit.form`) is perfectly legal — it is never parsed as a path.
- Passing `null` to the setter clears **every key in that hook's map** and leaves other search params alone. This is exactly `closeAll()` for an overlay group (D-10) — one call, one URL write, no manual key enumeration.
- A partial object updates only the named keys; `undefined` values are skipped (`if (... || value === undefined) continue` at `dist/index.js:575`), so `{ page: null }` clears `page` while leaving `q` untouched.

### 1.5 `createParser` / `createMultiParser`

```ts
type SingleParser<T> = {
  type?: 'single'
  parse: (value: string) => T | null      // return null (or throw — see below) for invalid input
  serialize?: (value: T) => string
  eq?: (a: T, b: T) => boolean            // used by clearOnDefault and keyMap stability
}
type MultiParser<T> = {
  type: 'multi'
  parse: (value: ReadonlyArray<string>) => T | null
  serialize?: (value: T) => Array<string>
  eq?: (a: T, b: T) => boolean
}

declare function createParser<T>(p: Require<SingleParser<T>, 'parse' | 'serialize'>): SingleParserBuilder<T>
declare function createMultiParser<T>(p: Omit<Require<MultiParser<T>, 'parse'|'serialize'>, 'type'>): MultiParserBuilder<T>
```

`createParser` **requires both `parse` and `serialize`** and defaults `eq` to `(a, b) => a === b` — the default is spread *before* your object, so your `eq` wins. `[VERIFIED: dist/index.js:77-92]`

A parser that **throws** inside `parse` is caught by nuqs's `safeParse`, logged via `warn(25, ...)`, and treated as `null`. `[VERIFIED: dist/index.js:62-70]` This means D-19's "unknown operators are dropped, never thrown" is satisfied structurally — but still return `null`/skip rather than throw, so no dev-console noise on a hand-edited URL.

Builder methods on the returned object: `.withOptions(options)`, `.withDefault(value)`, `.parseServerSide(value)` (deprecated in favour of `createLoader`).

### 1.6 `createSerializer`

```ts
type CreateSerializerOptions<P> = Pick<Options, 'clearOnDefault'> & {
  urlKeys?: UrlKeys<P>
  processUrlSearchParams?: (sp: URLSearchParams) => URLSearchParams
}
declare function createSerializer<P extends ParserMap>(parsers: P, opts?): {
  (values: Partial<Nullable<inferParserType<P>>>): string
  (base: string | URLSearchParams | URL, values: Partial<...> | null): string
}
```

`[VERIFIED: dist/index.d.ts:334-355, dist/index.js:382-443]`

Behaviour, exactly:

- **No base** → starts from an *empty* `URLSearchParams` and returns `"?a=1&b=2"` (or `""` when nothing is set). **This drops every other param in the current URL.**
- **Base is a `URLSearchParams`** → `splitBase` returns `["", new URLSearchParams(base), ""]`, so the result is still just `"?...merged..."` — existing params preserved, named params overwritten or deleted (`null` deletes).
- **Base is a string/URL** → path and hash are preserved and prefixed.

For D-10's `href()` this is decisive: **pass the current search params as the base**, or a link that opens an overlay will nuke the table's filters.

```ts
// packages/ui/src/query-state/overlays.tsx
const serialize = createSerializer(parsers, { urlKeys })

function useOverlayHref() {
  const searchParams = useSearchParams()          // ReadonlyURLSearchParams extends URLSearchParams
  return React.useCallback(
    (patch: Partial<Nullable<Values>>) => serialize(searchParams, patch) as Route,
    [searchParams]
  )
}
```

Two consequences the planner must encode:

1. **`typedRoutes: true` is on.** The generated `RouteImpl<T>` union includes a bare `` `?${string}` `` member (`apps/landlord-web/.next/dev/types/link.d.ts:12,60-66`), so a query-only href **type-checks and behaves as relative-to-current-path** — which is exactly what an overlay link wants. No `ROUTES.*` cast gymnastics needed; a single `as Route` at the `href()` boundary suffices. `[VERIFIED: generated route types in this repo]`
2. `useSearchParams()` returns the **committed** params, which lag nuqs's optimistic state by up to one flush window (~150 ms, §4). A link rendered immediately after a filter change can be one flush stale. Acceptable; note it rather than engineering around it.

### 1.7 `createLoader` / `createSearchParamsCache`

`createLoader(parsers, { urlKeys })` returns a function accepting a `URL | Request | URLSearchParams | Record<string, string|string[]> | string`, sync or `Promise`-wrapped, with `{ strict?: boolean }`. `createSearchParamsCache` lives in `nuqs/server`. **Both are explicitly deferred by CONTEXT.md** (no page SSR-prefetches list data). `[VERIFIED: dist/adapters/next/app.js]`

The auth routes under `app/auth/` are static but contain no nuqs consumers. **Plan action:** add an explicit `pnpm build` verification step; if a static route ever gains a nuqs consumer, wrap its client template in `<Suspense>` per `[CITED: nuqs.dev/docs/troubleshooting]`.

### 2.3 Adapter internals worth knowing

```js
// dist/impl.app-C0Tb8jcf.js
const NUM_HISTORY_CALLS_PER_UPDATE = 3;
function useNuqsNextAppRouterAdapter() {
  const router = useRouter();
  const pathname = usePathname();
  const [optimisticSearchParams, setOptimisticSearchParams] =
    useOptimistic(useSearchParams() ?? new URLSearchParams());
  return {
    searchParams: optimisticSearchParams,
    pathname,
    updateUrl: useCallback((search, options) => {
      startTransition(() => {
        if (!options.shallow) setOptimisticSearchParams(search);
        const url = renderURL(search);
        const updateMethod = options.history === 'push' ? history.pushState : history.replaceState;
        setQueueResetMutex(0);
        updateMethod.call(history, null, historyUpdateMarker, url);
        if (options.scroll) window.scrollTo(0, 0);
        if (!options.shallow) router.replace(url, { scroll: false });
      });
    }, []),
    rateLimitFactor: NUM_HISTORY_CALLS_PER_UPDATE,   // = 3
    autoResetQueueOnUpdate: false,
  };
}
```

`[VERIFIED: dist/impl.app-C0Tb8jcf.js:9-72]`

- `updateUrl` is `useCallback(..., [])` — **permanently stable**, which is a prerequisite for setter stability (§5).
- `rateLimitFactor: 3` means the effective minimum interval between URL writes on this adapter is **3 × 50 ms = 150 ms** (3 × 120 ms = 360 ms on Safari 17+). Every setter call inside that window coalesces.
- nuqs patches `history.pushState`/`history.replaceState` with a `"__nuqs__"` marker to distinguish its own writes from router navigations, and resets its queue on `popstate` and on pathname change (`NavigationSpy`).

## 3. Custom Parser for the D-18 Filter Encoding

### 3.1 The grammar — stated precisely

D-18's two examples are `status=any:s1,s2` (one predicate, two values) and `baseRent=gte:1500,lte:3000` (two predicates, one value each). These are unambiguous under exactly one rule:

> **Split the param value on `,` into tokens. A token containing `:` opens a new predicate — text before the first `:` is the operator, text after is its first value. A token without `:` appends another value to the currently-open predicate. A token whose `:`-suffix is empty (`empty:`, or the bare form `empty`) opens a valueless predicate.**

Formally:

```
param      := predicate ("," predicate)*
predicate  := operator (":" value ("," value)*)?
operator   := "!"? IDENT          ; "!" is the negation sugar for "!any" / "!empty"
value      := any character except ":" and ","
```

Worked examples:

| URL fragment | Tokens | Predicates |
|---|---|---|
| `status=any:s1,s2` | `any:s1`, `s2` | `[{ op: any, values: [s1, s2] }]` |
| `baseRent=gte:1500,lte:3000` | `gte:1500`, `lte:3000` | `[{ gte, [1500] }, { lte, [3000] }]` |
| `status=!any:s1,empty` | `!any:s1`, `empty` | `[{ !any, [s1, "empty"] }]` — **note the trap** |
| `status=!any:s1;empty` | — | see §3.2 |
| `squareFootage=!empty` | `!empty` | `[{ !empty, [] }]` |

**The trap in row 3 is real.** A valueless operator cannot be distinguished from a value when it follows a value-bearing predicate. Two mitigations, pick one in the plan:

- **(A, recommended)** Require valueless operators (`empty` / `!empty`) to be the **only** predicate on a field. This is already true semantically — `getEmptyFilterFlag` in `data-table-query.ts:145-155` collapses conflicting empty chips to "newest wins" anyway, and the existing `Filters` UI never produces `is_any_of` + `empty` on one field in a way that survives the server mapping (`applyServerMapping` writes `emptyParam` independently of the include list, so they don't actually conflict — but the URL grammar can't express both). Document it: **empty/not-empty is exclusive per field in the URL.**
- **(B)** Use `;` as the predicate separator and `,` as the value separator: `baseRent=gte:1500;lte:3000`, `status=any:s1,s2`. This is fully unambiguous with no exclusivity rule, and `;` is safe — the WHATWG URL spec splits query strings on `&` only, and nuqs's encoder does not escape `;` (§11.1). The cost is a one-character deviation from D-18's literal spelling.

**Value charset is safe today.** All filterable id values are Postgres `uuid` columns (`apps/server/src/schema/units.ts:10,37,41,49`) — hex plus hyphens, no `:` or `,`. Numeric fields serialize to digits. `[VERIFIED: codebase]` Add a dev-only assert in `serialize` so a future non-UUID option value fails loudly rather than silently corrupting a URL.

### 3.2 Implementation sketch

```ts
// packages/ui/src/query-state/table-params.ts
import { createParser } from "nuqs"
import type { Filter } from "../filters"

/** URL alias ↔ internal operator, per D-19. Only these are accepted. */
const URL_OP_TO_INTERNAL = {
  "any":    "is_any_of",
  "!any":   "is_not_any_of",
  "empty":  "empty",
  "!empty": "not_empty",
  eq: "eq", neq: "neq", gt: "gt", gte: "gte", lt: "lt", lte: "lte",
} as const
const INTERNAL_TO_URL_OP: Record<string, string> = Object.fromEntries(
  Object.entries(URL_OP_TO_INTERNAL).map(([url, internal]) => [internal, url])
)
const VALUELESS = new Set(["empty", "not_empty"])

type FieldFilter = Pick<Filter<string>, "operator" | "values">

/**
 * One filter field's predicates, e.g. `gte:1500,lte:3000` or `any:s1,s2`.
 * `allowedOperators` is the field's declared operator list — anything outside
 * it is dropped rather than thrown (D-19).
 */
export function parseAsFieldFilters(fieldKey: string, allowedOperators: readonly string[]) {
  const allowed = new Set(allowedOperators)

  return createParser<FieldFilter[]>({
    parse(query) {
      const out: FieldFilter[] = []
      for (const token of query.split(",")) {
        const colon = token.indexOf(":")
        if (colon === -1) {
          // Continuation value for the open predicate; ignore a stray leading one.
          out[out.length - 1]?.values.push(decodeValue(token))
          continue
        }
        const internal = URL_OP_TO_INTERNAL[token.slice(0, colon) as keyof typeof URL_OP_TO_INTERNAL]
        if (!internal || !allowed.has(internal)) continue   // drop, never throw
        const raw = token.slice(colon + 1)
        out.push({ operator: internal, values: raw === "" ? [] : [decodeValue(raw)] })
      }
      // Drop predicates that ended up empty-but-not-valueless (e.g. `gte:` alone).
      const cleaned = out.filter((p) => VALUELESS.has(p.operator) || p.values.length > 0)
      return cleaned.length > 0 ? cleaned : null
    },

    serialize(predicates) {
      return predicates
        .map((p) =>
          VALUELESS.has(p.operator)
            ? INTERNAL_TO_URL_OP[p.operator]!
            : `${INTERNAL_TO_URL_OP[p.operator]}:${p.values.map(encodeValue).join(",")}`
        )
        .join(",")
    },

    // REQUIRED: values are arrays of objects. Without this, clearOnDefault never
    // fires AND the keyMap-stability check in useQueryStates fails every render,
    // which un-memoizes the setter. See §5.
    eq(a, b) {
      if (a === b) return true
      if (a.length !== b.length) return false
      return a.every((pa, i) => {
        const pb = b[i]!
        return (
          pa.operator === pb.operator &&
          pa.values.length === pb.values.length &&
          pa.values.every((v, j) => v === pb.values[j])
        )
      })
    },
  })
    // Empty array = "no filter on this field" = param absent.
    .withDefault(EMPTY_PREDICATES)
}

/** Module-scope frozen singleton — a fresh `[]` per render breaks setter stability. */
const EMPTY_PREDICATES: FieldFilter[] = Object.freeze([]) as FieldFilter[]

// Escape the two grammar delimiters if a value ever contains them. UUIDs never
// do; this exists so a future non-UUID option value degrades instead of corrupting.
const encodeValue = (v: string) => v.replace(/~/g, "~~").replace(/:/g, "~c").replace(/,/g, "~s")
const decodeValue = (v: string) => v.replace(/~c/g, ":").replace(/~s/g, ",").replace(/~~/g, "~")
```

Three points a reviewer should check:

- **`eq` is not optional here.** `clearOnDefault` compares against `defaultValue` with `eq` (`dist/index.js:576`), *and* the keyMap-stability heuristic calls `parser.eq?.(previousDefault, currentDefault)` (`dist/index.js:494`). Omitting it costs you both a clean URL and a stable setter.
- **`withDefault(EMPTY_PREDICATES)` must reference a module-scope constant.** `.withDefault([])` inline creates a new array identity per render → `Object.is(previousDefault, currentDefault)` is false → falls through to `parser.eq?.(prev, curr)`, which *does* return true here, so it survives — but only because `eq` exists. Belt and braces: use the frozen constant.
- **`Filter.id` (D-24) is assigned by the caller, not the parser.** Keep the parser returning `{ operator, values }` and let `useDataTableQueryState` mint `` `${fieldKey}:${operator}:${index}` `` when assembling `Filter[]`. That is deterministic per D-24 and keeps the parser's `eq` free of an id it does not own.

Consequences:

1. **One `setTimeout(0)` per flush window.** All setter calls in the same tick land in one `updateMap`, one `updateUrl` call, one history entry. Calls in *different* ticks within 150 ms also coalesce, because `flush()` short-circuits to the already-pending promise.
2. **`push` is sticky within a flush window.** If an overlay opens (`history: 'push'`, D-12) while a table update (`history: 'replace'`, D-26) is queued, the merged write is a `push`. The reverse never downgrades a push to a replace. Practically benign — the resulting entry snapshots both states, which is what a shareable URL wants — but D-12 and D-26 are *not* independently guaranteed. State this in the plan rather than letting a tester discover it.
3. **`globalSingleton` is keyed by nuqs version on `globalThis`** (`dist/context-Mu913OAK.js:54-60`), so two copies of `nuqs@2.9.5` in a pnpm monorepo still share one queue. Two *different* versions would not — pin one version across the workspace.

### 5.2 `stableKeyMap` — the amendment to D-25


1. Build the parser map **once at module scope** inside `defineTable` (or `useMemo` with a `[]`-equivalent dep), never inline in the hook body.
2. Every parser whose `defaultValue` is an array or object **must** declare `eq` — the filter-predicate parser (§3.2) and the sort parser.

## 6. Hooks-in-Config (D-22)

### 6.1 Is it safe?

**Yes, under two conditions that the design already satisfies, plus one it must add.**

React's Rules of Hooks require that the *number, order, and type* of hook calls be identical across renders of a given component instance. Iterating a static, module-scope, never-reordered config and calling `field.useOptions()` per entry satisfies this — the loop is effectively unrolled to a fixed sequence. React 19 does not change this rule.

Real failure modes, ranked:

| Failure mode | Real? | Mitigation |
|---|---|---|
| **Conditional fields** — e.g. hiding the Property field when `lockedPropertyId` is set (which `units-filters.tsx:21` does today via `if (properties?.length)`) | **Yes — this is the live one.** `UnitsList` is mounted with and without `lockedPropertyId`, and the current code omits the Property field entirely in the locked case | **Always call every `useOptions()`; filter the *output* for display.** Never branch the iteration. The binder returns the full array; the caller drops hidden fields afterwards. Cheap: the hidden field's tRPC query is already deduped/cached, and it can be `enabled:false`-gated by the caller passing a `hidden` flag into the field's options hook |
| **Config reorder between renders** | No, if the config is a module-scope `const` array/object literal | Freeze it (`Object.freeze`) and document that entries must never be conditionally spread |
| **HMR reordering** | Only if the developer edits the config file — which triggers a full module re-evaluation and remount of consumers anyway. Worst case is a dev-only "Rendered fewer hooks than expected" that a refresh clears | Accept; note in the file header |
| **React Compiler** | Not applicable — `reactCompiler` is **not** enabled in `apps/landlord-web/next.config.mjs`. `[VERIFIED: codebase]` If enabled later, the compiler bails out of components it cannot prove safe, which degrades to today's behaviour rather than miscompiling | Re-evaluate if React Compiler is adopted |
| **`eslint-plugin-react-hooks` v7 error** | Yes. `packages/ui/eslint.config.mjs` sets `react-hooks/rules-of-hooks: "error"` | See §6.2 |

### 6.2 The narrowest correct disable

The rule fires per offending call site, so scope the disable to the single `useOptions()` line inside the binder, not to the function or file:

```ts
// packages/ui/src/query-state/table-params.ts
export function useBoundFilterFields(config: TableConfig): FilterFieldConfig[] {
  const fields: FilterFieldConfig[] = []
  // The config is a frozen module-scope object whose entry order never changes,
  // so this loop unrolls to a fixed hook sequence. Fields are never conditionally
  // skipped — hidden fields are filtered out of the *result*, not the iteration.
  for (const [key, field] of Object.entries(config.fields)) {
    // eslint-disable-next-line react-hooks/rules-of-hooks -- static, frozen, never-reordered config; see comment above.
    const options = field.useOptions?.() ?? field.options ?? []
    fields.push(toFilterFieldConfig(key, field, options))
  }
  return fields
}
```

This matches the repo's existing scoped-disable style (`unit-form-sheet.tsx:153`, `property-tab-groups.ts:5` — both `// eslint-disable-next-line <rule> -- <rationale>`). `[VERIFIED: codebase]`

### 6.3 A materially safer formulation that keeps ONE config object

If the "one frozen config, hooks called in a loop" contract feels too load-bearing, there is a formulation with **zero rule-of-hooks violation and still one config object**: give the binder a fixed hook budget by having `defineTable` return a purpose-built component-level hook whose body is *generated once* from the config at module-evaluation time.

```ts
// defineTable builds the binder at module scope, so the hook calls are written
// out into a single closure — one call per field, in source order, unconditional.
export function defineTable<C extends TableConfig>(namespace: string | null, config: C) {
  const entries = Object.entries(config.fields)          // captured once, at module load
  const optionHooks = entries.map(([, f]) => f.useOptions)

  function useFilterFields(): FilterFieldConfig[] {
    // Fixed-length array, fixed order, no branching — statically analysable by
    // the linter as a `.map` over a module-scope constant is not, but the loop
    // body is provably uniform. Still needs the disable; the win is that the
    // shape is locked at module load rather than per render.
    const optionSets = optionHooks.map((useOptions) =>
      // eslint-disable-next-line react-hooks/rules-of-hooks -- module-scope fixed-length hook list
      useOptions ? useOptions() : EMPTY_OPTIONS
    )
    return React.useMemo(() => entries.map(([k, f], i) => toFilterFieldConfig(k, f, optionSets[i]!)), optionSets)
  }
  return { useFilterFields, parsers: buildParsers(namespace, config), /* ... */ }
}
```

**Honest assessment: this does not remove the disable** — the linter cannot prove a `.map` over a module-scope array is fixed-length either. The genuine alternative is to stop calling hooks in a loop at all, by inverting to a small render-prop component per field (`<FieldOptionsBinder field={f} onResolved={...} />`), which costs a component per field and re-introduces the "options arrive asynchronously" problem D-23 exists to kill. **Recommendation: keep D-22 as written, add the "never conditionally skip a field" rule from §6.1, and take the one scoped disable.** The trade is correct.

## 7. Radix Controlled-Overlay Integration

`Dialog`, `Sheet`, and `Popover` in `@villuh/ui` are unmodified Radix passthroughs (`sheet.tsx:10-12`), so `{...overlay.dialogProps}` spreads directly. The four behaviours to get right:

### 7.1 Exit animation — the one that actually breaks

`SheetContent` and `DialogContent` rely on Radix's internal `Presence`, which keeps the content in the DOM through the `data-closed` exit animation (`sheet.tsx:40,65` — `data-closed:animate-out`, `duration-200`). This works **only if the `<Sheet>` root component stays mounted while `open` flips to `false`.**

- ✅ With D-08's always-mounted registry, this is automatic and free. The overlay component is permanently mounted; only `open` toggles. **Global mounting is a genuine argument in favour of D-08.**
- ❌ If anyone "optimises" by conditionally rendering the overlay on `isOpen` (a natural instinct, to avoid mounting cost), the exit animation is cut to zero frames and the sheet vanishes.
- The rule to encode: **gate the tRPC query on `isOpen`, never the JSX.**

### 7.2 Focus restoration

Radix restores focus to `document.activeElement`-at-open on close. This is unaffected by URL-driven state — the URL write is a `history.replaceState`, not a navigation, so React never unmounts the trigger. **One caveat:** if the trigger is a `<Link href={overlay.href(...)}>` (D-10) rendered inside a list that re-renders when the URL changes, and the link is not keyed stably, focus restoration targets a detached node and falls back to `<body>`. Keep row keys stable (they already are — `getRowId` defaults to `row.id`).

### 7.3 `onOpenChange(false)` on Escape / overlay click

Radix calls `onOpenChange(false)` for Escape, overlay click, and the close button. Wiring it to `overlay.close()` means each of those performs a `replace` (D-12) — correct, and no extra work. Two things to verify in the plan:

- `close()` must be **idempotent**. Radix can fire `onOpenChange(false)` more than once (e.g. Escape during an exit animation). Setting a param to `null` twice is harmless — nuqs's `updateMap.set(key, null)` is last-write-wins — but the second call still schedules a flush. Guard with `if (!isOpen) return` in `close()`.
- The `Promise<URLSearchParams>` returned by the setter should be explicitly voided (`void overlay.close()`) or awaited; an unhandled floating promise trips `@typescript-eslint/no-floating-promises` if it is ever enabled.

### 7.4 `forceMount` — not needed

**Recommendation: do not use `forceMount`.** With D-08, the Radix root is already permanently mounted, so `Presence` handles the exit animation and `forceMount` would only force the *portal contents* to stay in the DOM permanently — which costs DOM nodes, breaks the `data-closed` animation contract (you would then have to drive presence yourself), and makes hidden form fields focusable. The single case where `forceMount` would be needed is a page-mounted overlay inside a conditionally-rendered parent — i.e. the Lightbox (§9), which is not Radix anyway.

```tsx
// packages/ui/src/query-state/overlay-body.tsx
type OverlayQuery<TData> = {
  data: TData | undefined
  isLoading: boolean
  isError?: boolean
  error?: { message: string; data?: { code?: string } | null } | null
}

export function OverlayBody<TData>({ query, pending, notFound, forbidden, children }: {
  query: OverlayQuery<TData>
  pending: React.ReactNode
  notFound?: React.ReactNode
  forbidden?: React.ReactNode
  children: (data: TData) => React.ReactNode
}): React.ReactNode {
  if (query.isError) {
    const code = query.error?.data?.code
    if (code === "NOT_FOUND") return notFound ?? <EmptyState icon="IconQuestionCircle" title="Not found" description="This record no longer exists, or the link is out of date." />
    if (code === "FORBIDDEN") return forbidden ?? <EmptyState icon="IconLock" title="No access" description="You don't have permission to view this." />
    return <EmptyState icon="IconWarningSign" title="Something went wrong" description={query.error?.message || "Please try again."} />
  }
  // Mirrors PageBoundary: `data === undefined` also covers the disabled-query
  // window, so content never renders without data.
  if (query.isLoading || query.data === undefined) return pending
  return children(query.data)
}
```

There is **no jsdom, no `@testing-library/react`, no `@testing-library/user-event`, no browser-mode vitest anywhere in the monorepo.** This phase is entirely frontend. Standing up frontend test infrastructure is a real cost decision the plan must make explicitly rather than assume.

**What is testable with a genuinely small footprint:** the parsers. `nuqs/testing` ships `isParserBijective`, `testParseThenSerialize`, and `testSerializeThenParse` (introduced 2.4.0) `[CITED: nuqs.dev/docs/testing]`, and the D-18 parser is a pure function with no React and no DOM. A `vitest` project in `packages/ui` with the **default node environment** — no jsdom, no RTL — covers the highest-risk, highest-subtlety code in the phase (grammar parsing, operator validation, `eq`, `clearOnDefault` round-tripping) for roughly one config file.

**What would require new infrastructure:** anything rendering a component. `withNuqsTestingAdapter` from `nuqs/adapters/testing` makes it *possible* without mocking the router, but it still needs jsdom + `@testing-library/react` + `user-event` — a new toolchain in a repo that has none. Recommend deferring, and covering component behaviour by manual verification (CONTEXT already lists six concrete manual scenarios).

## 11. Known nuqs Pitfalls Relevant to This Design

### 11.1 Encoding of `:` and `,` — D-18's readability goal is safe

```js
// dist/context-Mu913OAK.js:19-32
function renderQueryString(search) {
  for (const [key, value] of search.entries()) {
    const safeKey = key.replace(/#/g,'%23').replace(/&/g,'%26').replace(/\+/g,'%2B')
                       .replace(/=/g,'%3D').replace(/\?/g,'%3F')
    query.push(`${safeKey}=${encodeQueryValue(value)}`)
  }
  ...
}
function encodeQueryValue(input) {
  return input.replace(/%/g,'%25').replace(/\+/g,'%2B').replace(/ /g,'+')
              .replace(/#/g,'%23').replace(/&/g,'%26').replace(/"/g,'%22')
              .replace(/'/g,'%27').replace(/`/g,'%60').replace(/</g,'%3C')
              .replace(/>/g,'%3E').replace(/[\x00-\x1F]/g, c => encodeURIComponent(c))
}
```

`[VERIFIED: dist/context-Mu913OAK.js:19-32]`

**`:` , `,` and `;` are all left untouched**, and so is `.` in the key (`unit.form` renders literally). nuqs uses a deliberately minimal encoder precisely to keep URLs pretty. `/units?q=main&status=any:s1,s2&baseRent=gte:1500,lte:3000&sort=-baseRent&page=2&size=50` will appear in the address bar exactly as written in D-18. **D-18 is achievable as specified.**

The one thing to avoid: do **not** hand-roll `encodeURIComponent` inside your serializer. `encodeQueryValue` escapes `%` first, so your `%3A` becomes `%253A` in the address bar (it does round-trip correctly through `URLSearchParams.get()`, but it is ugly and defeats the point). The `~c`/`~s` escapes in §3.2 avoid this entirely — `~` is not in nuqs's escape set.

### 11.2 URL length

`URL_MAX_LENGTH = 2000`, checked on every render of the query string, `console.warn`-ing error 414 in development only (`dist/context-Mu913OAK.js:33-40`). At 36 chars per UUID plus a separator, a single `property=any:...` filter accommodates roughly 50 selections before the warning. Realistic for a 1–50-unit landlord product. Not a blocker; do not engineer around it.

### 11.3 Hydration

No mismatch risk in this app. `NuqsAdapter` renders only a context provider on the server; all `useQueryState(s)` consumers are `"use client"` components under a dynamically-rendered layout, and the server render sees the real `searchParams`. The pages-router "always returns null on SSR" caveat does not apply to the App Router. `[CITED: nuqs.dev/docs/troubleshooting]`

### 11.4 Navigation away from a page with params

Two independent safeguards, both verified:

- `NavigationSpy` compares the previous pathname against `usePathname()` during render and calls `globalThrottleQueue.reset()` on change, so pending writes never land on the new page (`dist/impl.app-C0Tb8jcf.js:32-45`).
- `useQueryStates` tracks `committedPathnameRef` and skips reconciliation until the adapter's pathname matches, preventing a flash of the new page's (absent) params in the old component (`dist/index.js:502, 516-530`).
- On `popstate`, `onPopState` clears the reset mutex and calls `resetQueues()`.

**One ordering hazard the plan must specify.** `ArchiveUnitDialog` currently does `onOpenChange(false)` followed immediately by `router.push(...)` (`archive-unit-dialog.tsx:47-51`). Translated, that is `overlay.close()` (a queued `replace`, flushing in ≤150 ms) racing an immediate navigation. `NavigationSpy` resets the queue on the pathname change, so the pending close is dropped — which is correct, because the destination URL has no overlay param anyway. **Recommendation: when a mutation navigates away, drop the `close()` call entirely and just `router.push`.** Keep `close()` only where the user stays on the page.

### 11.5 Different parsers on the same key

Hooks sync per URL key. Two hooks binding the same key with different parsers will cross-contaminate (`[CITED: nuqs.dev/docs/troubleshooting]`). D-29's collision assert addresses exactly this — make the assert compare *resolved URL keys* (post-`urlKeys`), registered in a module-scope registry, and throw in development only.

### 11.6 Monorepo duplication (error 303 / 409)

nuqs guards against duplicate copies with `globalSingleton` keyed by `Symbol.for('nuqs.2.9.5.<scope>')` and a `globalWeakSingleton` for the adapter context, and warns `"Multiple adapter contexts detected. This might happen in monorepos."` (error 303) if `window.__NuqsAdapterContext` is reassigned. `[VERIFIED: dist/context-Mu913OAK.js:54-83]`

Practical consequence for D-03: `packages/ui` needs `nuqs` in `dependencies` (its hooks import it), **and each app needs `nuqs` in its own `dependencies`** to resolve `nuqs/adapters/next/app` under pnpm's strict layout. Pin the same exact version in both so the singleton scope key matches. The alternative — re-exporting `NuqsAdapter` from `@villuh/ui` — would put a `next/*` runtime import inside `packages/ui` for the first time (today `next` is peer + dev only), so prefer the direct app dependency.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---|---|---|---|
| 1-based URL page ↔ 0-based `pageIndex` | manual `+1`/`-1` | `parseAsIndex` | Already handles `null`, non-numeric, and the serialize side |
| `size` / `sort` allow-list validation | `if (!ALLOWED.includes(x))` | `parseAsNumberLiteral(DATA_TABLE_PAGE_SIZES)`, `parseAsStringLiteral(sortableIds)` | Returns `null` → falls back to default, and types the state literal |
| Batching several setters into one history entry | `useRef` + microtask coalescer | just call the setters; or one `useQueryStates` call | Global throttle queue already does this (§4) |
| Memoizing the nuqs setter | custom `useEventCallback` | the setter is already `useCallback`-wrapped | Fix the *cause* of churn (`defaultValue` identity + missing `eq`), not the symptom |
| Clearing every key in a group | enumerate keys and null each | `setParams(null)` | Clears exactly that hook's keys, one write |
| Building an overlay `href` | template-string concatenation | `createSerializer(parsers, { urlKeys })(searchParams, patch)` | Preserves other params, honours `clearOnDefault` and `urlKeys`, uses the same encoder as the hooks |
| Percent-escaping delimiters in values | `encodeURIComponent` | a non-`%` escape (`~c`/`~s`) or a value charset guarantee | nuqs escapes `%` → `%25` first, producing double-encoded, unreadable URLs (§11.1) |
| Overlay loading / not-found / forbidden UI per overlay | per-component branches | `OverlayBody`, copied from `PageBoundary` | D-15; the analog already exists at `page.tsx:98-159` |
| Parser round-trip tests | ad-hoc assertions | `isParserBijective` from `nuqs/testing` | Tests both directions and throws with which side failed |

**Key insight:** nuqs's value here is not `useState`-in-the-URL — it is the throttle/batch/history queue and the parser contract. Every hand-rolled piece above re-implements a part of that queue badly.

## Common Pitfalls

### Pitfall 1: Unstable setter kills the search debounce

**What goes wrong:** typing in the table search box never commits.
**Why:** `DataTableToolbar`'s effect lists `onQueryChange` in its deps (`data-table-toolbar.tsx:51-59`). An unstable setter re-arms the 300 ms timer every render, so it never fires. The cause is a per-render `defaultValue` identity in the nuqs keyMap combined with a missing `eq` (§5.2).
**How to avoid:** module-scope frozen parser map; `eq` on every array/object parser; `useCallback` on the adapter wrapper.
**Warning sign:** the URL never gains `?q=` while typing, but does the moment you blur and click something else.

### Pitfall 2: Conditionally-skipped filter fields break the rules of hooks

**What goes wrong:** `Rendered fewer hooks than during the previous render` when navigating between `/units` and a property Units tab.
**Why:** the current `createUnitsFilterFields` skips the Property field when `lockedPropertyId` is set (`units-filters.tsx:21`). Ported naïvely into a hooks-in-config binder, that becomes a conditional hook call.
**How to avoid:** always iterate every field and call every `useOptions()`; filter the *result* for display (§6.1).
**Warning sign:** the crash only appears on the *second* render after a route change.

### Pitfall 3: Every overlay's queries fire on every page

**What goes wrong:** every authenticated page load issues `properties.list`, `unitStatuses.list`, `tags.listOrganizationTags`, …
**Why:** globally-mounted overlay components run their hooks unconditionally. `UnitFormSheet` currently has two ungated queries (`unit-form-sheet.tsx:86-87`).
**How to avoid:** `{ enabled: overlay.isOpen }` on every query in every registered overlay. `ArchivePropertyDialog` is the in-repo reference.
**Warning sign:** the Network tab shows list queries on `/settings`.

### Pitfall 4: Conditional rendering cuts the exit animation

**What goes wrong:** the sheet disappears instantly instead of sliding out.
**Why:** `{overlay.isOpen && <UnitFormSheet .../>}` unmounts the Radix root before `Presence` can run the `data-closed` animation.
**How to avoid:** gate the query, never the JSX (§7.1).

### Pitfall 5: `href()` without a base drops the table filters

**What goes wrong:** clicking a row's "Edit" link opens the sheet on an unfiltered table.
**Why:** `createSerializer(parsers)(values)` starts from an empty `URLSearchParams` (§1.6).
**How to avoid:** always `serialize(searchParams, patch)`.
**Warning sign:** the URL after clicking contains only the overlay param.

### Pitfall 6: `nuqs` resolvable in `@villuh/ui` but not in the app

**What goes wrong:** `Cannot find module 'nuqs/adapters/next/app'` at build time.
**Why:** pnpm's strict `node_modules` — a transitive dependency of a workspace package is not importable from the app.
**How to avoid:** add `nuqs` to both apps' `dependencies` at the same pinned version (§11.6).

### Pitfall 7: `push` leaking into a table update

**What goes wrong:** twelve filter changes leave twelve back-button entries — the exact thing D-26 forbids.
**Why:** an overlay `push` in the same ≤150 ms flush window makes the whole merged write a `push` (§4).
**How to avoid:** it cannot be fully prevented, only bounded. Do not fire an overlay open and a table update from the same handler. Verify the D-26 scenario (rapid filter changes with no overlay interaction) explicitly rather than assuming.

### Pitfall 8: `useParams()` typed as non-optional in a global mount

**What goes wrong:** `propertyId` is `undefined` at runtime on `/units` while TypeScript insists it is a `string`; `toFormValues` receives `undefined` where it expected `""`.
**Why:** all five existing call sites use `useParams<{ propertyId: string }>()`, which is a lie once the component is reachable from routes without the segment.
**How to avoid:** `useParams<{ propertyId?: string }>()` in every globally mounted overlay.

## Code Examples

### Overlay group (D-07 / D-10 / D-12 / D-13)

```ts
// packages/ui/src/query-state/overlays.tsx
"use client"
import * as React from "react"
import { useQueryStates, createSerializer, parseAsString, type UrlKeys } from "nuqs"
import { useSearchParams } from "next/navigation"

const OVERLAY_OPTIONS = { scroll: false } as const           // shallow:true is the default

export function createOverlays<const N extends string, C extends Record<string, OverlayDef>>(
  namespace: N,
  defs: C
) {
  // Module-scope: built once, so `stableKeyMap` never churns (§5.2).
  const parsers = Object.freeze(
    Object.fromEntries(Object.keys(defs).map((name) => [name, parseAsString]))
  ) as { [K in keyof C]: typeof parseAsString }

  const urlKeys = Object.freeze(
    Object.fromEntries(Object.keys(defs).map((name) => [name, `${namespace}.${name}`]))
  ) as UrlKeys<typeof parsers>

  const serialize = createSerializer(parsers, { urlKeys })

  function useGroup() {
    const [values, setValues] = useQueryStates(parsers, { ...OVERLAY_OPTIONS, urlKeys })
    const searchParams = useSearchParams()

    return React.useMemo(() => {
      const handles = {} as { [K in keyof C]: OverlayHandle }
      for (const name of Object.keys(defs) as (keyof C)[]) {
        const value = values[name]
        const isOpen = value !== null
        handles[name] = {
          isOpen,
          value,
          // D-12: open pushes, close replaces.
          open:   (v = "new") => void setValues({ [name]: v } as never, { history: "push" }),
          close:  ()          => { if (isOpen) void setValues({ [name]: null } as never, { history: "replace" }) },
          toggle: (v = "new") => (isOpen ? handles[name].close() : handles[name].open(v)),
          dialogProps: {
            open: isOpen,
            onOpenChange: (next: boolean) => (next ? handles[name].open() : handles[name].close()),
          },
          // Base = current params, so a link preserves table filters (§1.6).
          href: (v = "new") => serialize(searchParams, { [name]: v } as never),
        }
      }
      return { ...handles, closeAll: () => void setValues(null) }
    }, [values, setValues, searchParams])
  }

  return { defs, parsers, urlKeys, useGroup }
}
```

### Table query state twin (D-28)

```ts
// packages/ui/src/query-state/use-data-table-query-state.ts
"use client"
import * as React from "react"
import { useQueryStates } from "nuqs"
import { buildDataTableServerInput, type DataTableQuery } from "../data-table-query"
import { DATA_TABLE_DEFAULT_PAGE_SIZE } from "../data-table"

const TABLE_OPTIONS = { history: "replace", scroll: false } as const   // D-26

export function useDataTableQueryState<TInput = Record<string, unknown>>(table: TableDefinition) {
  // `table.parsers` and `table.urlKeys` are frozen module-scope objects built by
  // defineTable — required for setter stability (§5.2).
  const [values, setValues] = useQueryStates(table.parsers, { ...TABLE_OPTIONS, urlKeys: table.urlKeys })
  const filterFields = table.useFilterFields()          // the hooks-in-config binder (§6)

  const query = React.useMemo<DataTableQuery>(() => ({
    search: values.q,
    // D-24: ids are regenerated deterministically from field + operator + index.
    filters: table.fieldKeys.flatMap((key) =>
      (values[key] as FieldFilter[]).map((p, i) => ({
        id: `${key}:${p.operator}:${i}`, field: key, operator: p.operator, values: p.values,
      }))
    ),
    sorting:   values.sort ?? undefined,
    pageIndex: values.page,
    pageSize:  values.size,
  }), [values])

  const setQuery = React.useCallback((next: DataTableQuery) => {
    void setValues({
      q:    next.search || null,
      sort: next.sorting ?? null,
      page: next.pageIndex ?? 0,
      size: next.pageSize ?? DATA_TABLE_DEFAULT_PAGE_SIZE,
      ...table.toFieldParams(next.filters),
    })                                                   // ONE call → ONE history entry (§4)
  }, [setValues])

  const serverInput = React.useMemo(
    () => buildDataTableServerInput(query, filterFields) as TInput,   // D-30: unchanged
    [query, filterFields]
  )

  return { query, setQuery, serverInput, filterFields }
}
```

## Decisions Requiring Revision

### D-08 / D-11 — the gallery Lightbox cannot be globally mounted

**Problem.** D-08 mandates that every registered overlay is mounted by a single `<AppOverlays>` at `(app)/layout.tsx`, and D-09 that overlays receive their handle as a prop and are self-sufficient. The Lightbox violates both by construction: it needs `originRef`, a live `HTMLElement` handle to the clicked thumbnail, for its shared-element zoom (`lightbox.tsx` `landing()` reads `origin.getBoundingClientRect()`). A DOM ref is neither serializable into a URL nor threadable from a page-level grid to a layout-level mount. It also needs the `properties.gallery.list({ propertyId })` result to resolve D-11's image id into a URL, and it currently renders inside `Page.Boundary`'s render prop.

Global mounting would silently downgrade every lightbox open — not just deep links — to the generic fade fallback.

**Alternative.** Split *state ownership* from *mount location*, which D-08 does not actually forbid once stated plainly:

- The lightbox param (`gallery.photo=<imageId>`) is registered in `properties.overlays.ts` exactly like every other overlay, so it participates in D-13's namespacing, D-29's collision assert, `closeAll()`, and `href()`.
- `AppOverlays` skips entries flagged `mount: "page"` (a one-word addition to the registry entry).
- `property-gallery-template.tsx` calls the group hook itself and renders `<Lightbox open={h.isOpen} onClose={h.close} originRef={originRef} src={images.find(i => i.id === h.value)?.url ?? ""} />`, keeping `originRef` local. On a cold deep link `originRef.current` is `null` and `landing()` already degrades gracefully — correct behaviour, no special case.

This preserves every user-visible guarantee (shareable link, back closes it, id-not-index) and the per-feature cost target, at the price of one enum field in the registry. **Recommend amending D-08 to "every overlay is *registered* once; overlays flagged `mount: 'page'` are rendered by their page"** and adding the flag to D-11.

### D-25 — necessary but not sufficient

**Problem.** D-25 states `setQuery` must be referentially stable "(`useCallback` over nuqs's stable setters)". The premise that nuqs's setters are stable is *conditionally* true: `useQueryStates`'s `update` has `stableKeyMap` in its dependency array, and that stabilization fails when a parser's `defaultValue` is a new non-primitive reference each render and the parser has no `eq` (§5.2). A `useCallback` over an unstable dependency is not stable.

**Alternative.** Restate D-25 as three requirements, all cheap:

1. `setQuery` is wrapped in `useCallback` with `[setParams]` as its only dep. *(as written)*
2. The parser map and `urlKeys` object are built **once at module scope** by `defineTable` / `createOverlays` and frozen — never constructed inside the hook body.
3. Every parser with a non-primitive `defaultValue` (the filter-predicate parser, the sort parser) **declares `eq`**. This is independently required for `clearOnDefault` (D-20) to work at all.

Add a verification step: assert setter identity is stable across a re-render, or simply verify the D-27 acceptance criterion (typing in search produces exactly one URL write after 300 ms) — it fails loudly if any of the three is violated.

### D-12 + D-26 — the two history policies are not independent

**Problem.** D-12 sets overlays to `push`-on-open and D-26 sets all table state to `replace`, described as independent inverse policies. nuqs's global throttle queue merges all updates in a ≤150 ms window into one history write and applies `push` if *any* contributing update requested it (`ThrottledQueue.push`: `if (options.history === 'push') this.options.history = 'push'`). The two policies therefore interact.

**Alternative.** This is not a design flaw so much as an unstated behaviour, and the merged result is arguably desirable (one history entry capturing both the overlay and the table state — precisely the shareable-link goal). **No change to the decisions; add a note to D-26** stating that a table update coalesced with an overlay open inherits `push`, and scope the acceptance test to "twelve filter changes with no overlay interaction require one back press."

*No other locked decision was found to be technically unsound. D-01 through D-07, D-09, D-10, D-13 through D-24, and D-27 through D-30 are all supported by the verified API surface.*

## Security Domain

`security_enforcement` is not set to `false`, so this section is included. This phase moves **UI state** into the URL and changes no authorization boundary.

### Applicable ASVS Categories

| ASVS Category | Applies | Standard Control |
|---|---|---|
| V2 Authentication | no | Unchanged — Better Auth; `requireMe()` still gates the `(app)` subtree |
| V3 Session Management | no | Unchanged |
| V4 Access Control | **indirectly** | A deep link is a *request*, not a grant. Every overlay fetch goes through the same tRPC procedures under RLS; `withOrganization` still scopes reads. A pasted link to another org's unit yields `NOT_FOUND` (§8.1) — no existence oracle |
| V5 Input Validation | **yes** | Every URL param is attacker-controlled. Parsers must be total functions returning `null` on anything unexpected: `parseAsStringLiteral` / `parseAsNumberLiteral` for `sort`/`size`, explicit operator allow-list for filters (D-19), and server-side Zod re-validation of the resulting tRPC input (already in place, unchanged) |
| V6 Cryptography | no | No crypto in scope |
| V7 Error Handling & Logging | **yes** | `OverlayBody` must not surface raw server error messages beyond the existing `PageBoundary` behaviour; the NOT_FOUND copy must not distinguish "does not exist" from "not yours" |

### Known Threat Patterns

| Pattern | STRIDE | Standard Mitigation |
|---|---|---|
| Crafted param values injected into a tRPC list input | Tampering | Client parsers allow-list operators and column ids; server Zod schemas re-validate independently. **Never** widen a server schema to accommodate a URL shape |
| Reflected XSS via a param rendered into the DOM | Tampering | React escapes text nodes by default; the only param-derived rendering here is inside `Filter` chips and entity ids passed to tRPC. No `dangerouslySetInnerHTML` anywhere in the touched files |
| Information disclosure through error discrimination | Information Disclosure | RLS already collapses cross-org reads to `NOT_FOUND`. Keep the FORBIDDEN branch generic and do not add a "this belongs to another organization" message |
| Sensitive identifiers leaking via `Referer` header or shared links | Information Disclosure | Overlay params carry UUID primary keys, which are already present in path segments (`/units/<uuid>`). No new class of data enters the URL. Do not put email addresses, tokens, or names in a param |
| Open redirect | Tampering | None introduced — `href()` produces a query-only string appended to the current pathname; no param is ever used as a navigation target |
| Denial of service via an enormous URL | DoS | Bounded by the browser and nuqs's 2000-char dev warning; server list inputs already have Zod bounds |

## Open Questions

1. **Does the plan stand up frontend test infrastructure, or accept manual verification?**
   - What we know: nothing exists today; the parsers are pure and testable with a node-environment vitest project alone; component tests need a whole new toolchain.
   - What's unclear: whether the project wants frontend tests generally, which is a bigger decision than this phase.
   - Recommendation: Wave 0 adds the node-environment vitest project to `packages/ui` for parsers only. Defer jsdom/RTL.

2. **D-18 grammar: exclusive-empty rule, or `;` predicate separator?**
   - What we know: both are unambiguous; the exclusive-empty rule preserves D-18's literal spelling, `;` is strictly more general.
   - Recommendation: exclusive-empty rule (option A, §3.1). It matches D-18 verbatim and the semantics are already effectively exclusive in the existing `getEmptyFilterFlag`.

3. **Lazy overlay loading — deferred, or built now?**
   - What we know: CONTEXT defers it; the registry makes it a one-line change later; the shared-chunk cost at five overlays is small but monotonically increasing.
   - Recommendation: keep deferred, but shape the registry entry type so `component: Component | (() => Promise<{ default: Component }>)` is a non-breaking addition, and note the first-open animation caveat (§9.1).

4. **Does anything else need `mount: "page"` besides the Lightbox?**
   - What we know: only the Lightbox has a non-serializable dependency among the five migrations.
   - Recommendation: add the flag, use it once, and treat any second use as a signal to revisit D-08.
