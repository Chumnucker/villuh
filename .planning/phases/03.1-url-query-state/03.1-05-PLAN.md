Four things that will bite if you deviate:

- **The field object keys ARE the URL keys.** `property` → `?property=any:...`, `baseRent` → `?baseRent=gte:1500`. They are also the `field` value on every emitted `Filter` chip and the key `buildDataTableServerInput` looks up the `server` mapping by, so they must stay exactly the four keys `createUnitsFilterFields` used today: `property`, `status`, `baseRent`, `squareFootage`. Renaming one is a URL-contract break, not a refactor.
- **`sortable` must equal `UNIT_SORT_KEYS`** — a sort id the server rejects becomes a 400 on a shared link. `propertyName` stays sortable even on the property Units tab where that column is hidden; the server accepts it and hiding a column is not the same as forbidding a sort.
- **No `type:` property.** `defineTable` derives `type: "multiselect"` from `ids` and `type: "text"` from `numeric`, matching what `createUnitsFilterFields` set by hand.
- **`useMemo` inside `useOptions` is unconditional** — it runs after the `useQuery` on every call, hidden or not, so the hook sequence inside the field is fixed too.

Do **not** add an eslint disable to this file. The only one in the phase lives on the `useOptions` call line inside `define-table.tsx`; the `useOptions` *declarations* here are ordinary function expressions and lint has no complaint about them.
