# Phase 03.1 Plan 03: defineTable & useDataTableQueryState Summary

**`defineTable` turns a table's filter/sort/page config into one frozen module-scope object, and `useDataTableQueryState` is a drop-in URL-backed replacement for `useDataTableQuery` — same return signature, deterministic chip ids, one `replace` setter call, and `buildDataTableServerInput` fed unchanged. The three query-state modules are now reachable through the `@villuh/ui` barrel, proven by a green landlord-web build.**

## Performance

- **Duration:** ~25 min
- **Completed:** 2026-08-13
- **Tasks:** 3 of 3
- **Files:** 5 (3 created, 2 modified)

## What was built

### Task 1 — `defineTable`, `ids()`/`numeric()`, and the `useFilterFields` binder
- `packages/ui/src/query-state/define-table.tsx` (`"use client"`). Builds a frozen `parsers` map (`q`/`sort`/`page`/`size` + one `parseAsFieldFilters` per field) and a frozen `urlKeys` object, once at module evaluation (D-41). Registers under the definition-unique `name` so the D-29 guard fires on a second unprefixed table.
- `ids()`/`numeric()` field constructors thread each field's `operators`, `server` mapping, and optional `useOptions(hidden)` into `TableFieldDef`.
- `useFilterFields({ hide })` calls every field's `useOptions` on every render (fixed hook sequence) and filters hidden fields out of the result — the loop's single `react-hooks/rules-of-hooks` disable is the only eslint disable in the whole `query-state/` folder.
- `define-table.test.ts` — 11 tests: unprefixed vs `:`-prefixed urlKeys, frozen-map + stable identity, the D-29 collision throw (different names, both `namespace: null`, shared `q`) vs same-name HMR tolerance, `toFieldParams` inverse, and operator-allow-list threading (`empty` dropped for `nullable:false`).

### Task 2 — `useDataTableQueryState`
- `packages/ui/src/query-state/use-data-table-query-state.ts` (`"use client"`). One `useQueryStates(table.parsers, { history: "replace", scroll: false, urlKeys })` call; `query` memoized off the frozen `values`, minting deterministic ids `` `${key}:${p.operator}:${index}` `` (D-24); `setQuery` is a `useCallback([setParams, table])` issuing a single atomic `setParams(...)` (D-25/D-41); `serverInput` from `buildDataTableServerInput` unchanged (D-30). Returns `{ query, setQuery, serverInput, filterFields }` (D-28). No parser is constructed in the hook body.

### Task 3 — barrel + runtime build gate
- Added `define-table`, `table-params`, and `use-data-table-query-state` to `packages/ui/src/index.ts` (query-state block now has 8 `export *` lines). No sub-barrel; the package `exports` map is unchanged.
- **D-39 build gate caught a real defect:** exporting `table-params` from the (server) barrel dragged it into the RSC graph, where nuqs's client-only `parseAsIndex.withDefault` is a proxy and threw `is not a function`. Fixed by adding `"use client"` to `table-params.ts`. `pnpm turbo run build --filter=@villuh/landlord-web` now exits 0.
