# Phase 3.1: URL Query State (nuqs) - Context

**Gathered:** 2026-08-13
**Status:** Ready for planning
**Type:** INSERTED (decimal phase after Phase 3)

<domain>
## Phase Boundary

Every openable overlay (dialog, sheet, lightbox) and every data table's filter/sort/pagination state moves into the URL as query params, driven by `nuqs`. A pasted link restores exactly what the sender saw: the same filtered, sorted, paginated table with the same overlay open on the same record. The abstraction is built once in `@villuh/ui` so that adding a new overlay costs one config line plus the component, and adding a new table filter costs one config line.

This phase is cross-cutting infrastructure plus the migration of all existing landlord-web consumers. It changes no server code, no database schema, and no tRPC contracts.

**Explicitly out of this phase's build:** intercepting/parallel routes (rejected — see D-01/D-02), server-side param reading via nuqs `createSearchParamsCache` / `createLoader` (no page SSRs list data today), and resident-web overlay/table consumers (none exist yet — resident-web gets the adapter only).

</domain>

<decisions>
## Implementation Decisions

### Mechanism choice
- **D-01:** All route-like overlay state and all table query state use **`nuqs` (v2.9.5, supports Next 16)**. Next.js **intercepting routes and parallel routes are explicitly rejected** — no `@modal` slots, no `default.tsx`, no route folders per overlay. The route tree is untouched apart from mounting the adapter.
- **D-02:** Rationale for rejecting intercepting routes: their only unique capability is the SSR'd full-page-on-reload twin, and **no Villuh surface needs one** (confirmed: not the gallery lightbox, not future document viewers). They also cannot express two overlays open at once, cannot compose with table filter state in one shareable URL, and only intercept on soft navigation from a matching path. The app fetches everything client-side via tRPC and has zero SSR data dependency, so they buy nothing.
- **D-03:** `nuqs` is a dependency of **`@villuh/ui`** (core hooks are framework-agnostic). `<NuqsAdapter>` from `nuqs/adapters/next/app` is mounted as the outermost provider inside `<body>` in **both** apps' root layouts.
- **D-04:** Primitives live in **`packages/ui/src/query-state/`** and are re-exported from `src/index.ts`. They must be barrel-exported because the package's `"./*"` wildcard export maps only to `./src/*.tsx` — `.ts` modules are unreachable via the wildcard (same reason `data-table-query.ts` routes through the barrel today).

### Overlay model
- **D-05:** One universal rule: **param absent = closed, param present = open, and the param value is the payload** (an entity id, or a literal mode such as `new`). This covers dialogs, sheets, lightboxes, and anything else openable.
- **D-06:** **Full deep linking.** A cold load of `/units?unit.form=unit_abc` opens the sheet and fetches `unit_abc` itself. Overlays are self-sufficient — they never receive a row object from a parent.
- **D-07:** Overlays are declared **once per module** in `modules/{module}/{module}.overlays.ts` via `createOverlays(namespace, { name: entity(Component) })`. The registry holds the component, so there is no separate mount step to remember.
- **D-08:** A **single global `<AppOverlays modules={[...]} />`** is mounted in `app/(app)/layout.tsx`. Registering a module happens once; after that, adding an overlay is one line in that module's config plus writing the component.
- **D-09:** An overlay component **receives its handle as an `overlay` prop** from `<AppOverlays>` and never imports its own registry — this avoids a registry↔component import cycle and keeps the component testable in isolation.
- **D-10:** Overlay handle API: `isOpen`, `value`, `open(value?)`, `close()`, `toggle(value?)`, `dialogProps` (`{ open, onOpenChange }` — spreads directly onto Radix `Dialog`/`Sheet`/`Popover`), and `href(value?)` built with nuqs `createSerializer` so a trigger can be a real `<Link>` that right-click-opens in a new tab. The group also exposes `closeAll()`.
- **D-11:** `Lightbox` is not Radix (`open` + `onClose`, custom portal). It gets a **thin `onClose` → `onOpenChange` adapter**; the primitive itself is not rewritten. Its param value carries the **image id, not the array index** — indexes shift when the gallery is reordered or an image is deleted, which would silently point a shared link at the wrong photo.
- **D-12:** **History semantics for overlays: open = `push`, close = `replace`.** Browser back closes an open overlay; closing via UI does not strand a forward entry that re-opens it. Both use `scroll: false` and nuqs's default shallow mode.
- **D-13:** URL keys are namespaced `{namespace}.{name}` (e.g. `unit.form`) via nuqs's **`urlKeys`** option on a single `useQueryStates` call per group, so a group updates atomically.
- **D-14:** **Mount context comes from the route, not props.** `UnitFormSheet`'s `lockedPropertyId` prop is removed; on `/properties/[propertyId]/units` the overlay reads the property from `useParams()`. This is required for global mounting and is consistent with D-06.
- **D-15:** A shared **`<OverlayBody>`** handles the deep-link failure modes once: loading skeleton, not-found, and forbidden. No overlay reimplements them.
- **D-16:** **Not everything goes in the URL.** A state belongs in the URL only if a user could meaningfully link to it or expect back to undo it. Popovers, dropdown menus, tooltips, and error-triggered dialogs stay on local `useState`. Specifically: `TagPicker`'s popover stays local; `LimitReachedDialog` (opened by `PlanLimitGate` after a rejected action) stays local; `TagIconColorPicker` stays uncontrolled.
- **D-17:** The per-overlay tRPC fetch-by-id stays **explicit** in each overlay component. Different endpoints and inputs make it genuine business logic, not boilerplate worth another abstraction layer.
- **D-17a:** Triggers wrapped in **`PlanLimitGate` must remain buttons calling `open()`**, never `<Link href={overlay.href(...)}>`. The gate has to intercept the click and show `LimitReachedDialog` when the org is at cap; a link would navigate straight past it. `href()` is for ungated triggers only (row actions, detail links).

### Table query state
- **D-18:** Serialization is **one readable param per filter field**, with operator encoded as `op:value` and multiple predicates on one field comma-separated:
  `/units?q=main&status=any:s1,s2&baseRent=gte:1500,lte:3000&sort=-baseRent&page=2&size=50`
  Chosen over a single delimited param or `parseAsJson` because URLs stay human-readable and hand-editable, which is the point of sharing them.
- **D-19:** URL operator aliases are short (`any` = `is_any_of`, `!any` = `is_not_any_of`, `empty` / `!empty`, plus the numeric ops `eq`/`neq`/`gt`/`gte`/`lt`/`lte`). Each parsed operator is **validated against that field's declared operator list; unknown or unsupported operators are dropped, never thrown.**
- **D-20:** `sort` is a single param with a leading `-` for descending (`sort=-baseRent`), validated against sortable column ids. `page` is **1-based in the URL** and converted to the 0-based `pageIndex` the table uses. `size` carries page size. `clearOnDefault` keeps an untouched table's URL completely clean.
- **D-21:** **One config object per table**, `modules/{module}/{module}.table.ts`, via `defineTable(namespace, { field: ids({...}) | numeric({...}) })`. A single field declaration carries label, icon, operators, nullability, the existing `server` mapping, and its options source. Adding a filter is one line; URL parsing, operator validation, picker UI, and tRPC input mapping all derive from it.
- **D-22:** Filter **options are supplied by a `useOptions` hook inside the field declaration** (e.g. `useOptions: () => useOptionsFrom(trpc.properties.list, …)`), so the config is a single static module-scope object rather than a static schema plus a runtime binder. Accepted cost: the binder calls hooks while iterating the config, which is safe because the config never reorders but unprovable to `eslint-plugin-react-hooks` — **one scoped eslint disable inside the single binder function**, nowhere else. Note `react-hooks/rules-of-hooks` is configured as `error` (not `warn`) in `packages/ui`, so the disable is load-bearing for the build, not cosmetic.
- **D-23:** This resolves the current blocker that `createUnitsFilterFields(properties, statuses)` returns `[]` until tRPC lists resolve, which would otherwise make URL parsing inconsistent on first paint.
- **D-24:** `Filter.id` is a client-generated chip identity. The parser **regenerates ids deterministically** from field + operator + position, otherwise every URL read produces fresh ids and churns React keys.
- **D-25:** `setQuery` must be **referentially stable** (`useCallback` over nuqs's stable setters). `DataTableToolbar`'s search-debounce effect depends on `onQueryChange` identity and will thrash otherwise.
- **D-26:** **History semantics for table state are the inverse of overlays: `replace`** for filters, search, sort, and pagination. Nobody should need twelve back presses to escape a table they were filtering.
- **D-27:** Search debounce **stays in `DataTableToolbar`** (300ms, existing). nuqs only ever sees committed search values.
- **D-28:** `useDataTableQuery` is replaced by a URL-backed twin with an **identical return signature** (`{ query, setQuery, serverInput }`, plus `filterFields`). `DataTable`, `DataGrid`, column defs, and the toolbar are **not modified**.
- **D-29:** **Key-collision rules.** Overlay keys are *always* namespaced with a dot (`unit.form`). Table keys are *unprefixed by default* (`q`, `status`, `sort`, `page`, `size`) because one table per page is the norm and unprefixed keys read best in a shared link. A table opts into a prefix (`units:status`) only when a page hosts more than one table. The two schemes must not converge on the same string — table prefixes therefore use `:` and overlay namespaces use `.`, and the primitives assert at dev time that no two registered keys collide.
- **D-30:** `buildDataTableServerInput` and the whole `data-table-query.ts` mapping layer are **kept as-is** — the URL layer sits above them.

### Amendments from pattern mapping (2026-08-13)

- **D-31:** **Two mount modes, one registry.** D-08's "everything mounts globally" is too strong. `entity(Component)` registers an **auto-mounted** overlay that `<AppOverlays>` renders and hands its handle to as a prop. `entity()` with **no component** registers the key only — the component is **placed manually** where it needs DOM refs or local context, and imports its own handle (`galleryOverlays.use("photo")`), which is cycle-free precisely because the registry does not reference the component. Both forms live in the same config object, so the key stays centrally declared and typed either way.
- **D-32:** The **gallery Lightbox is manually placed** (D-31, second form). It sets `originRef.current = e.currentTarget` on thumbnail click for its shared-element zoom, and a live DOM handle to the clicked thumbnail cannot reach a globally mounted component. It still becomes URL-backed — `open` and the active image come from the image-id param (D-11) instead of `useState` — it simply renders where it does today.
- **D-33:** On a **cold deep link there is no origin element**, so `Lightbox` must tolerate `originRef.current === null` and fall back to a plain fade rather than a zoom. Verify this against the current implementation; if it doesn't hold, fixing it is in scope.
- **D-34:** **`<AppOverlays>` mounts inside `<UserProvider>` and outside `<PageTransition>`.** Inside `UserProvider` is mandatory — `ManageTagsDialog` calls `useUser()` for its `write` permission check. Outside `PageTransition` is mandatory — that's a `ViewTransition` keyed on pathname, and an open overlay inside it would fade or remount on navigation.
- **D-35:** No overlay in the migration list consumes `usePropertyDetail()`, so the page-level property provider is **not** a blocker for global mounting. `ArchivePropertyDialog` takes `propertyId` / `propertyName` as props today, but it already self-fetches `properties.get` gated on `open` and that response carries `property.name` — so **both props are dropped at zero extra network cost.**
- **D-36:** **Every overlay's tRPC queries must gate on `isOpen`.** `UnitFormSheet` currently runs two ungated queries; once auto-mounted app-wide, ungated queries would fire on every page load for every registered overlay.
- **D-37:** Module config files live at **`modules/{module}/lib/{module}.overlays.ts`** and **`lib/{module}.table.ts`**, not at module root. Every existing non-component module file sits one level down under `lib/`; following the repo convention beats following nuqs's `searchParams.ts`-at-root idiom, and stops a future reviewer from "fixing" the placement.
- **D-38:** `useParams()` generics must be **optional** (`useParams<{ propertyId?: string }>()`) for any overlay reachable from more than one route. The five existing call sites all declare `{ propertyId: string }`, which is a lie on `/units` where no such param exists.
- **D-39:** Acceptance must include a **runtime import-resolution check**, not just `typecheck`. The tsconfig path alias for `@villuh/ui` is more permissive than the package `exports` map, so a new `query-state/` module can typecheck cleanly and still fail to resolve at runtime (this is the concrete failure mode D-04 exists to prevent).
- **D-40:** `packages/ui` has **no runtime `next` import today** — `nuqs/adapters/next/app` would be the first. Keep the adapter import in the **apps**, not in `@villuh/ui`, so the design system stays framework-agnostic and `resident-web` isn't forced into a Next-coupled path it doesn't use.

### Amendments from research (2026-08-13)

- **D-41:** **D-25 was necessary but not sufficient.** nuqs already `useCallback`-wraps its setters, but the dependency array includes a `stableKeyMap` that destabilizes when a parser's `defaultValue` is a fresh non-primitive each render and the parser declares no `eq`. Wrapping an unstable dependency in `useCallback` does nothing. The full requirement is three parts: (1) `setQuery` wrapped in `useCallback` with `[setParams]` as its only dep; (2) the parser map and `urlKeys` object built **once at module scope** by `defineTable` / `createOverlays` and frozen, never constructed in a hook body; (3) **every parser with a non-primitive `defaultValue` declares `eq`** — the filter-predicate parser and the sort parser both qualify, and `eq` is independently required for `clearOnDefault` (D-20) to work at all. Violating any of the three re-arms `DataTableToolbar`'s 300 ms timer forever and the search box never commits.
- **D-42:** **D-12 and D-26 are not independent policies.** nuqs's throttle queue is a global singleton that merges every update within a ~150 ms window into one history write, and applies `push` if *any* contributing update asked for it. A table update coalesced with an overlay open therefore inherits `push`. This is acceptable and arguably correct — one history entry capturing both the overlay and the table state is exactly the shareable-link goal — but it must be stated, and the D-26 acceptance test is scoped to "twelve filter changes **with no overlay interaction** require one back press."
- **D-43:** Use nuqs's built-in **`parseAsIndex`** for D-20's 1-based-URL / 0-based-state page conversion. Do not hand-roll it.
- **D-44:** **`FORBIDDEN` is unreachable on a deep-link read.** RLS turns cross-organization access into `NOT_FOUND` before any authorization check runs. `<OverlayBody>` (D-15) still implements the branch for correctness, but **no acceptance test asserts it** — a test would be asserting a state the system cannot produce.
- **D-45:** D-18's readable URLs work exactly as specified — nuqs's encoder deliberately leaves `:` and `,` untouched, so `status=any:s1,s2&baseRent=gte:1500,lte:3000` renders literally. The grammar resolving the two examples' apparent conflict: **a token containing `:` opens a new predicate; a token without one appends a value to the current predicate.** All current filter values are UUIDs or numbers, but the parser carries `~c` / `~s` escapes for literal commas and colons plus a dev-only serializer assert, so a future value containing a delimiter fails loudly instead of silently mis-parsing.
- **D-46:** **There is no frontend test infrastructure anywhere in the monorepo** (`vitest` exists in `apps/server` only; no jsdom, no Testing Library). Wave 0 adds a **node-environment vitest project to `packages/ui`** covering the pure parsers only — grammar, bijectivity, operator validation, deterministic ids, `eq`, and the D-29 collision assert. Component-level behaviour is **manual verification** for this phase; standing up jsdom + Testing Library is explicitly out of scope.
- **D-47:** D-31/D-32's two mount modes are implemented as a **`mount: "page"` flag** on the registry entry. `<AppOverlays>` skips flagged entries; they still participate in D-13 namespacing, the D-29 collision assert, `closeAll()`, and `href()`. The gallery Lightbox is the only current user.
- **D-48:** Add **`pnpm turbo run build --filter=@villuh/landlord-web`** to the phase gate. It is the only check that catches a static-generation / CSR-bailout regression from introducing `useSearchParams`-backed hooks. The risk is believed low because every `(app)` route is already dynamic via `requireMe()`, but the build is the only thing that proves it.

### Amendment: shell portability (2026-08-13)

- **D-49:** **Every shell command in a plan — acceptance criteria, `<automated>` blocks, verification sweeps — must run in Windows PowerShell 5.1.** This is the developer's actual shell (verified `5.1.26100.9168`), and it is not bash. Concretely:
  - **No `&&` or `||` chaining.** PowerShell 5.1 has neither; `a && b` is a parser error, not a runtime failure. Use `;` for sequencing, and separate criteria lines when the second command must only run on success.
  - **No `grep`.** It does not exist on this machine. Use **`rg`** (available, and already this repo's search tool). Flag mapping: `grep -rn` → `rg -n` (rg recurses by default), `grep -q` → `rg -q`, `grep -c` → `rg -c`, `grep -rl` → `rg -l`.
  - **No `find`.** `find` resolves to `C:\WINDOWS\system32\find.exe`, Windows' string-search utility with entirely different semantics — it fails *quietly wrong* rather than loudly. Use `Get-ChildItem -Recurse` with a `Where-Object` filter, or `rg --files`.
  - **No `2>/dev/null`, `|| true`, `wc -l`, `head`, `tail`, or heredocs.** Use `Measure-Object` for counts; drop the noise-suppression idioms.
  - **Git ranges use `master`, not `main`** — this repository's default branch is `master`.
  - **`rg` takes a regex, `grep -F`-style literals need `-F`.** Most criteria here match source text containing `(`, `)`, `[`, `]`, `{`, `}`, `$` — all regex metacharacters. Unescaped, they silently match the wrong thing rather than erroring: `rg -q 'useState("")'` reads `("")` as a group and matches bare `useState`. Use `rg -qF` for literal source text; reserve bare `rg -q` for genuine patterns.
  - **`\|` is not alternation in `rg`.** It is a literal pipe. `grep`'s BRE `a\|b` must become `rg 'a|b'`, or the criterion matches nothing and reads as a (false) pass on a "returns non-zero" check.
  - **Escape inner double quotes as `\"` in any pattern passed to a native executable.** PowerShell 5.1 strips them otherwise — `rg -qF 'sortable: ["label"]'` reaches rg as `sortable: [label]` and fails. Write `rg -qF 'sortable: [\"label\"]'`. Single-quoted PowerShell strings are literal, so `$` and backticks inside them are safe and need no escaping. **One exception:** a pattern that both *begins* with `\"` and contains a space is split into two argv entries (`\"use client\"` arrives as `["use` and `client"`), so rg reads the second half as a path. Drop the quotes from the pattern instead and match the inner text.
  - **`-E` is not "extended regex" in `rg`; it is `--encoding`.** `rg -qE 'a|b'` exits `2` with `unknown encoding`. That is non-zero, so it *satisfies* any "returns non-zero" criterion and becomes a silent pass. Regex is ripgrep's default — drop the `E` entirely.
  - **No POSIX `diff`.** In PowerShell 5.1 `diff` is an alias for `Compare-Object`, which compares its two arguments as objects — for two paths, that means comparing the path *strings*, reporting differences between identical files. Use `Compare-Object (Get-Content a) (Get-Content b)`.
  - **No glob in a path argument.** PowerShell does not expand globs for native commands, so `rg -n 'X' apps/*/app/layout.tsx` hands rg a literal `*` and exits `2` with `os error 123`. Name the files, or use rg's own `--glob` flag.
  - **These rules govern shell syntax only, never quoted source text.** The no-`&&` rule is about command chaining; a pattern like `rg -qF 'enabled: overlay.isOpen && unitId !== null'` is TypeScript inside a quoted argument and must keep its `&&`. Same for `;`, `|`, and `$` appearing inside a pattern.
  - **A criterion may not be gated by text the same task mandates.** Several criteria here assert a token is *absent* from a file whose required doc comments contain that very token (`throw`, `encodeURIComponent`, the sequential-decode warning). Strip comments before searching — `(Get-Content $f) -replace '//.*$','' | Where-Object { $_ -notmatch '^\s*\*' }` — or the criterion is unsatisfiable, and the executor's cheapest escape is to delete the comment or rewrite the code the criterion exists to protect.

  This is a verification-mechanism constraint, not a design constraint: an acceptance criterion that cannot execute is not a criterion, and a `find`-based sweep that silently does the wrong thing is worse than no sweep at all. **Run every criterion before recording it, especially the ones expected to return non-zero** — a malformed command, an unknown flag, and a genuine pass are indistinguishable by exit code alone. Every rule above was added after a criterion that looked correct turned out to test nothing.

<specifics>
## Specific Ideas

- The measure of success is per-feature cost, not lines saved: **adding a filter = one config line; adding an overlay = one config line plus the component.** If a plan's design requires touching a third place, the abstraction is wrong.
- The `useState` trio (`sheetOpen`, `editingUnit`, `archivingUnit`) that currently appears in three separate templates is the specific duplication being deleted.
- URLs should be readable enough to hand-edit. If a shared link looks like percent-encoded JSON, D-18 was implemented wrong.
- Overlay params and table params must coexist in one URL — a link carrying both a filtered table and an open record is the headline use case.

### Suggested wave shape (planner may revise)
1. **Primitives, no behavior change** — `nuqs` dep, adapters in both root layouts, `query-state/` modules (`createOverlays`, `entity`/`flag`, `AppOverlays`, `OverlayBody`, `defineTable`, `ids`/`numeric`, `useDataTableQueryState`), barrel exports.
2. **Units table migration** — `units.table.ts`, swap both mounts, namespace to prevent cross-talk.
3. **Overlay migration** — units module, then properties module, then the gallery lightbox adapter.
4. **Cleanup** — delete `useDataTableQuery`, delete dead props, delete `createUnitsFilterFields`'s old shape.

### Verification (must be demonstrated, not assumed)
- Cold-load a pasted URL carrying both filters and an open edit sheet; both restore.
- Browser back closes an open overlay **without** clearing filter state.
- An invalid or non-permitted id in `?unit.form=` renders the not-found/forbidden state, not a blank sheet.
- The `/units` table and the property Units tab do not cross-talk when both are reachable.
- Typing in search does not spam history entries; twelve filter changes do not require twelve back presses.
- An untouched table produces a bare URL with no query string.

</specifics>
