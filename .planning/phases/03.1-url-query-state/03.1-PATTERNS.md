2. **Outside `<PageTransition>` is mandatory** — `PageTransition` is a `ViewTransition` keyed on the pathname/tab-group base (`app/(app)/page-transition.tsx`); putting overlays inside it would fade/remount every open overlay on navigation.

`AppLayout` is `async` (Server Component). `AppOverlays` will be `"use client"`, which composes fine — a Server Component may render a client child.

Three distinct precedents exist; `query-state/` needs all three.

**(c) Sub-folder conventions.** Three sub-folders exist and they do *not* agree, so pick deliberately:

| Folder | Has `index.ts`? | Reached from `src/index.ts` how? |
|---|---|---|

Since D-04 requires public reachability, follow the `metric-card` route: add explicit lines to `src/index.ts`. A `query-state/index.ts` sub-barrel is optional; if added, it must still be re-exported from `src/index.ts` or it repeats the `charts/` mistake (invisible to consumers).

**Why the barrel is mandatory — verified.** `packages/ui/package.json`:

`"./*": "./src/*.tsx"` — a `.ts` module has **no** subpath entry, so `@villuh/ui/query-state/overlays` cannot resolve. (A `.tsx` module *would* resolve via the wildcard, e.g. `@villuh/ui/query-state/app-overlays`, but mixing resolution routes within one folder is worse than routing everything through the barrel.) Note the tsconfig path alias `"@villuh/ui/*": ["./src/*"]` (`packages/ui/tsconfig.json:7`) is *more* permissive than the runtime exports map — typecheck can pass while resolution fails. Barrel only.

**Naming.** Flat kebab-case `{feature}-{type}.ts(x)`. Hook-only modules use a `use-` prefix (`charts/use-chart-interaction.ts`, `charts/use-mount-progress.ts`, `utils/use-presigned-upload.ts`) — which is why `use-data-table-query-state.ts` fits and `overlays.ts` / `table-params.ts` fit.
