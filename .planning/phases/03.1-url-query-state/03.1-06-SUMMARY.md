# Phase 03.1 Plan 06: Units Overlays to URL Summary

**Both units overlays (plus the org unit-status catalog) now live in the URL. They are declared once in `units.overlays.ts`, each component fetches its own record by the param value gated on `isOpen`, reads its route context from `useParams()`, and is mounted exactly once app-wide by `<LandlordOverlays />` in the `(app)` layout. The `useState` overlay state is gone from `UnitsList` and `unit-template.tsx`; `/units?unit.form=<id>` is now a shareable deep link.**

## Performance

- **Duration:** ~45 min
- **Completed:** 2026-08-13
- **Tasks:** 3 of 3 (all `type=auto`)
- **Files:** 9 (2 created, 7 modified)

## What was built

### Task 1 — registry + self-sufficient `UnitFormSheet`
`units.overlays.ts` declares `form`/`archive` (`entity`) and `statuses` (`flag`, the deviation). `UnitFormSheet({ overlay })` derives create-vs-edit from `overlay.value` (`"new"` → create, id → edit), fetches its unit via `trpc.units.get` gated on `overlay.isOpen && unitId !== null`, reads the create-mode property lock from `useParams<{ propertyId?: string }>()` (optional generic, D-38), renders edit through `OverlayBody`, and mounts `<Sheet {...overlay.dialogProps}>`. The form body was extracted to a keyed inner `UnitFormBody` (`mode` derived from `unit`), which deleted the reset `useEffect` and its `exhaustive-deps` disable; the option queries live inside it (unmounted while the sheet is closed, so no `enabled` flag needed). Both mutation invalidate lists survived byte-for-byte. Added a `UnitFormSkeleton` matching the field layout.

### Task 2 — self-sufficient `ArchiveUnitDialog` + both call sites
`ArchiveUnitDialog({ overlay })` fetches the unit label by id gated on open and renders through `OverlayBody`. The post-archive redirect target is snapshotted (`propertyIdOfUnit`) inside the render prop before `mutate`, and the per-call `onSuccess` calls `handleArchived(propertyIdOfUnit)` — no `unitQuery.data` read inside `onSuccess`. Redirect now fires only when on the archived unit's own detail page (`params.unitId === unitId`); archiving from the property Units tab no longer bounces the user (intentional change). `UnitsList` dropped its `useState` trio (and the overlooked `statusesOpen`), wired `const { form, archive, statuses } = unitOverlays.useGroup()`, rewired the columns memo (`form.open(unit.id)` / `archive.open(unit.id)`), the Add-unit button (`form.open()`, still a `<Button>` inside `<PlanLimitGate>`, D-17a), and the Manage-statuses item (`statuses.open()`); all overlay JSX removed. `unit-template.tsx` dropped both `useState`s and both overlay renders.

### Task 3 — the global mount
`app-overlays.tsx` holds `const MODULES = [unitOverlays]` behind a `"use client"` boundary and exports `LandlordOverlays`. The `(app)` layout renders `<LandlordOverlays />` as a sibling of `LayoutTemplate`, inside `UserProvider`, outside `PageTransition` (D-34). `ManageUnitStatusesDialog` became `({ overlay })`, gated its list query on `overlay.isOpen`, kept `useUser()` (the concrete reason the mount sits inside `UserProvider`), and both of its call sites now trigger the global overlay.
