# Phase 03.1 Plan 07: Properties Overlays to URL Summary

**All three remaining landlord-web overlays are URL-backed. `propertyOverlays` declares the cascade-archive confirm and the org tag catalog (global) plus the gallery photo key (page-mounted). Both dialogs fetch their own data gated on `isOpen`; the type-the-name confirm and the tag composer/popover stay on local state (D-16); the gallery Lightbox is now keyed on image id while still rendering on its own page for the shared-element zoom. Registering the properties module was the promised one-line MODULES edit.**

- **Duration:** ~35 min

- **Files:** 7 (1 created, 6 modified)

## What was built

### Task 1 — registry + `ArchivePropertyDialog`
`properties.overlays.ts` declares `archive` (`entity`), `tags` (`flag`), `photo` (`pageEntity`). `ArchivePropertyDialog({ overlay })` fetches property + unit cascade via `properties.get` gated on `overlay.isOpen && propertyId !== null` and statuses via `unitStatuses.list` gated on `isOpen`, rendering through `OverlayBody` with an `ArchivePropertySkeleton`. The confirm body moved into a keyed `ArchivePropertyConfirm` (`key={propertyId ?? "none"}`) owning `confirmName` — the only reset mechanism; `{...overlay.dialogProps}` is spread untouched. `header.tsx` dropped its `useState` (kept for `loadedHero`), triggers `archive.open(property.id)`, and no longer mounts the dialog.

### Task 2 — `ManageTagsDialog` + `TagPicker`
`ManageTagsDialog({ overlay })` gates its list query on `overlay.isOpen`, spreads `overlay.dialogProps`, closes via `overlay.close()`, and keeps `useUser()` (commented as the reason the mount sits inside `UserProvider`, D-34) — no `OverlayBody` (a list, not a by-id read). `TagPicker` dropped `manageOpen`, pulls `propertyOverlays.use("tags")`, both "Manage tags…" triggers call `manageTags.open()`, both dialog renders are gone (the `isInline` branch collapses to `chips`), and `popoverOpen`/`search`/`creating`/`newIcon`/`newColor` stay local (D-16).

### Task 3 — gallery Lightbox + module registration
`property-gallery-template.tsx` dropped both `useState`s and the `GalleryImage` type, pulls `propertyOverlays.use("photo")`, derives `active` from `images.find(i => i.id === photo.value)` (D-11), writes `originRef.current` on click then `photo.open(image.id)`, gates the Lightbox on `active !== null`, and adapts `onClose={photo.close}`. `app-overlays.tsx`: `const MODULES = [unitOverlays, propertyOverlays]`.
