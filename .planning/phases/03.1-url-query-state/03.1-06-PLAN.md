<objective>
Move both units overlays into the URL. Declare them once in `modules/units/lib/units.overlays.ts`, make each component self-sufficient (fetch its own record by the param value, read its route context from `useParams()`), mount `<AppOverlays>` once in the `(app)` layout, and delete the `useState` trio from both call sites.

Purpose: this is the plan that proves the overlay half of the abstraction. After it, `/units?unit.form=<id>` is a link a landlord can send to a colleague, and adding the next unit overlay costs one line in `units.overlays.ts`.

Output: the units module's overlay config, two rewritten overlay components, two call sites reduced to `open(...)` calls, and the single app-wide mount that plan 03.1-07 will extend with one more entry.

```ts
function OverlayBody<TData>(props: {
  query: { data: TData | undefined; isLoading: boolean; isError?: boolean; error?: { message: string; data?: { code?: string } | null } | null }

  notFound?: React.ReactNode
  forbidden?: React.ReactNode

}): React.ReactNode

type OverlayHandle = {
  isOpen: boolean
  value: string | null
  open: (value?: string) => void   // STABLE across renders
  close: () => void                // STABLE across renders
```

```tsx
export function UnitFormSheet({ overlay }: { overlay: OverlayHandle }) {

  // propertyId), /properties/[propertyId]/units, and /units/[unitId].
  // Declaring `{ propertyId: string }` here would be a lie on two of the three.

    { enabled: overlay.isOpen && unitId !== null }

  return (

      <SheetContent className="sm:max-w-md">
        <SheetHeader>
          <SheetTitle>{unitId ? "Edit unit" : "Create unit"}</SheetTitle>
        </SheetHeader>

            key="create"
            unit={undefined}
            // D-14: mount context comes from the route, not a prop. On the

            // /units it is free. Edit mode never locks it — reassigning a unit

}
```

**Snapshot the redirect target BEFORE calling `mutate`.** `onSuccess` runs after `invalidateQueries` resolves, by which point `units.get` has already refetched for a now-archived unit, so `unitQuery.data?.property.id` read inside the closure is almost certainly `undefined` — the redirect would silently take the `ROUTES.units` fallback every time and nobody would notice, because the fallback is a plausible-looking destination. Capture the id at click time, in the same handler that fires the mutation:

```tsx

  // Read OUTSIDE the onSuccess closure. After invalidation the unit is
  // archived and `unitQuery.data` is gone; reading it there yields undefined
  // and silently degrades every redirect to the ROUTES.units fallback.
  const propertyIdOfUnit = unit.property?.id ?? null

  return (
    …
    <Button
      variant="destructive"
      onClick={() =>
        archiveUnit.mutate(
          { unitId: unit.id },
          { onSuccess: () => handleArchived(propertyIdOfUnit) }
        )
      }
    >…</Button>
  )
}}
```

```tsx
const handleArchived = (propertyIdOfUnit: string | null) =>
```
