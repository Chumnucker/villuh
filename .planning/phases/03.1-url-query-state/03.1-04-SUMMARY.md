## Accomplishments

- `createOverlays(namespace, defs)` builds its parser map and `urlKeys` **once at module evaluation** and freezes both (`Object.freeze` appears exactly twice), registers every resolved key through `registerQueryStateKeys` for the D-29 collision assert, and dot-namespaces every key as `{namespace}.{name}`.
- The handle implements D-10 exactly, with the stability split the downstream plans depend on: `open` / `close` / `toggle` are memoized on nuqs's setter alone and are stable across URL changes; `isOpen` / `value` / `dialogProps` / `href` change with the URL. `close()` short-circuits when the param is already `null`, so Radix firing `onOpenChange(false)` twice during an exit animation schedules one flush, not two. `closeAll()` is a single `setValues(null, …)` write.
- **`buildOverlayHref` is an exported pure function, not a closure inside `useGroup`** (D-10), with a **required** `base` parameter — the structural defence against Pitfall 5. Three tests assert it directly, and the base-merge test carries a control that calls the same serializer *without* a base and asserts the other params are gone, so the test can actually fail if the base is ever dropped.
- `<AppOverlays>` renders one `OverlayGroupMount` child per group, so `useGroup()` is a normal top-level hook call rather than a hook inside a `.map` — which is why the file needs no eslint disable. It adds no DOM, never gates overlay JSX on open state, and uses no `forceMount`.
- `<OverlayBody>` is a structural copy of `PageBoundary` widened to discriminate `NOT_FOUND` from `FORBIDDEN` from a generic error, keeps the `query.data === undefined` guard that covers the disabled-query window, and keeps its not-found copy free of any tenancy language so RLS's collapse of cross-tenant reads into NOT_FOUND does not get undone by the UI.
- All five `query-state/` modules are reachable through the `@villuh/ui` barrel, and `pnpm turbo run build --filter=@villuh/landlord-web` still prerenders 12/12 static pages with no CSR bailout.

## Deviations from Plan

### 1. [Rule 1 — Bug] The plan's `AnyOverlayGroup` makes `<AppOverlays modules>` unsatisfiable

- **Found during:** Task 2, by a test added under Rule 2 (see Deviation 2).
- **Issue:** the plan specifies `type AnyOverlayGroup = OverlayGroup<Record<string, OverlayDef>>`. Erasing the key union turns `OverlayHandles<C>` into a `string` index signature valued `OverlayHandle`, and `useGroup()` also returns `closeAll: () => void` in that same object. TypeScript therefore rejects **every** concretely-typed group:

  ```
  Type 'OverlayGroup<{ readonly form: OverlayDef; readonly photo: OverlayDef; }>'
    is not assignable to type 'AnyOverlayGroup'.
      Property 'closeAll' is incompatible with index signature.
        Type '() => void' is not assignable to type 'OverlayHandle'.
  ```

  `app-overlays.tsx` compiles fine on its own — there is no call site in this plan — so this would have shipped green and failed in 03.1-06, at the `<AppOverlays modules={[unitsOverlays, propertiesOverlays]} />` mount, which is that plan's whole point.
- **Fix:** replaced the alias with the erased shape the mount actually consumes, widening the index value type to `OverlayHandle | (() => void)` so `closeAll` is legal, and narrowing once at the single read (`handles[name] as OverlayHandle`) with a comment stating why the narrowing is sound (`closeAll` is never a key in `defs`). The public prop keeps its meaning; `types.ts` and the D-10 contract are unchanged.
- **Files modified:** `packages/ui/src/query-state/app-overlays.tsx`
- **Verification:** `pnpm turbo run typecheck` 12/12 with the assignability test in place; the test fails to compile if the alias is reverted.
- **Committed in:** `a5ed77f`

### 2. [Rule 2 — Missing critical coverage] Compile-time assignability test added

- **Found during:** Task 2, before writing the file — the plan's `<files>` for Task 2 lists only `app-overlays.tsx`, and nothing in the plan exercises `AppOverlays`'s props until 03.1-06.
- **Issue:** a component whose only job is to accept registered groups had no check that it accepts one. The variance of a `const`-generic factory's output against an erased consumer type is exactly the kind of thing that is fine in the sketch and wrong in the compiler.
- **Fix:** added a 15th test to `overlays.test.ts` assigning a real `createOverlays(...)` result to `React.ComponentProps<typeof AppOverlays>["modules"]` via a type-only import, with a runtime `expect` so it is a genuine test rather than a dangling annotation. It found the bug in Deviation 1 on its first run.
- **Files modified:** `packages/ui/src/query-state/overlays.test.ts`
- **Verification:** 15/15 passing; reverting the Deviation-1 fix reproduces the compile error.
- **Committed in:** `a5ed77f`
