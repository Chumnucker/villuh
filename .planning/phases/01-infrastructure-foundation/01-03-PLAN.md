**Step 1: Create packages/db/src/schema/landlords.ts** (RLS-enabled table using current Drizzle API):
```typescript
import { sql } from 'drizzle-orm'
import { pgPolicy, pgRole, pgTable, text, timestamptz, uuid } from 'drizzle-orm/pg-core'

// Mark villuh_app as an EXISTING role — Drizzle should not try to CREATE it.
// The role is created by bootstrap-db.sql (run once by a superuser before migrations).
export const villuhApp = pgRole('villuh_app').existing()

/**
 * Demonstration table for RLS + audit log integration test.
 * Every table that holds tenant data follows this pattern:
 * - landlord_id NOT NULL column
 * - pgPolicy using current_setting('app.current_landlord_id', true)::uuid
 * - RLS enabled via .withRLS() on the table
 *
 * 'landlords' itself does NOT get RLS (bootstrap paradox — can't filter on itself).
 */
export const testTenantData = pgTable('test_tenant_data', {
  id: uuid('id').primaryKey().defaultRandom(),
  landlordId: uuid('landlord_id').notNull(),
  data: text('data'),
  createdAt: timestamptz('created_at').defaultNow().notNull(),
}, (t) => [
  pgPolicy('tenant_isolation', {
    as: 'permissive',
    for: 'all',
    to: villuhApp,
    using: sql`landlord_id = current_setting('app.current_landlord_id', true)::uuid`,
    withCheck: sql`landlord_id = current_setting('app.current_landlord_id', true)::uuid`,
  }),
]).withRLS()
```

Note: `.withRLS()` on the table call enables `ALTER TABLE ... ENABLE ROW LEVEL SECURITY` in the generated migration. The `pgPolicy(...)` entries inside the array are the actual filter rules.

Create packages/db/scripts/bootstrap-db.sql:
```sql
-- Run this ONCE as a Postgres superuser before running any Drizzle migrations.
-- Purpose: Create the villuh_app non-owner role that Drizzle's pgPolicy references.
-- If villuh_app already exists, the IF NOT EXISTS prevents an error.

-- 1. Create the non-owner runtime role
CREATE ROLE villuh_app NOSUPERUSER NOCREATEDB NOCREATEROLE NOINHERIT LOGIN PASSWORD 'villuh_app_password_changeme';

-- 2. Allow villuh_app to connect to the database (replace 'villuh' with your DB name if different)
GRANT CONNECT ON DATABASE villuh TO villuh_app;

-- 3. Allow villuh_app to use the public schema
GRANT USAGE ON SCHEMA public TO villuh_app;

-- 4. Grant DML on all CURRENT tables
GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO villuh_app;

-- 5. Grant DML on all FUTURE tables automatically
ALTER DEFAULT PRIVILEGES IN SCHEMA public
  GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO villuh_app;

-- After running this script, set environment variables:
--   DATABASE_URL=postgres://owner_user:password@localhost:5432/villuh
--   DATABASE_APP_URL=postgres://villuh_app:villuh_app_password_changeme@localhost:5432/villuh
--   DATABASE_TEST_URL=postgres://villuh_app:villuh_app_password_changeme@localhost:5432/villuh_test
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| migration client (owner) → Postgres | Full DDL access — must never be used at runtime |
| runtime client (villuh_app) → Postgres | Restricted DML — RLS enforced at DB layer |
| bootstrap-db.sql → superuser session | One-time setup — requires human to run as superuser |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Elevation of Privilege | Two connection strings | mitigate | DATABASE_URL (owner) is ONLY in migrate.ts and drizzle.config.ts — never imported by packages/server. Enforced by code structure. |
| T-03-02 | Information Disclosure | RLS bypass via owner role | mitigate | runtime client in src/index.ts uses DATABASE_APP_URL only; code comment explicitly forbids swapping; integration test in Plan 05 confirms RLS is enforced |
| T-03-03 | Information Disclosure | villuh_app password in bootstrap-db.sql | mitigate | bootstrap-db.sql uses placeholder password `villuh_app_password_changeme` — developer must change before use; file is committed to repo (it's a script, not a secret) |
| T-03-04 | Tampering | pgRole not .existing() | mitigate | villuhApp declared as `.existing()` — Drizzle will not attempt CREATE ROLE DDL; role is pre-created by bootstrap-db.sql |
</threat_model>
