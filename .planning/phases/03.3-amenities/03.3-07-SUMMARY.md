## Decisions Made
- **propertyId from `useParams`, not `usePropertyDetail()`.** The plan's `key_links` suggested `usePropertyDetail().propertyId`, but `AmenitySheet` is rendered by the global `<AppOverlays>` mount, which lives OUTSIDE `PropertyDetailProvider`; `usePropertyDetail()` throws when its context is absent, and the overlay component's hooks run on every page. `useParams<{ propertyId?: string }>()` matches the `UnitFormSheet` analog and is correct on cold load (the amenity sheet is only reachable from a property route). The list query is org-scoped server-side (RLS + `requirePropertyAmenity`), so a foreign/stale id resolves to not-found (T-033-18 mitigated).
- **Catalog Restore via a session-local recently-archived bucket.** `amenities.catalog.list` returns only non-archived rows and no archived-list endpoint exists in the D-28 contract, so archived rows are held in local state after archiving to keep Restore reachable in-session (satisfies the "archive then restore" flow without inventing a server endpoint).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `amenities/schemas.ts` relative `.js` cross-module import broke the client build**
- **Found during:** Task 1 (first build with the amenities schema pulled into the landlord client bundle)
- **Issue:** `apps/server/src/modules/amenities/schemas.ts` imported `../tags/schemas.js`; Turbopack could not resolve the explicit `.js` on a cross-module relative path when the file entered the client graph via `amenityOverlays` → components → `@villuh/server/schemas/amenities`. Build failed with `Module not found: Can't resolve '../tags/schemas.js'`.
- **Fix:** Swapped to the package export alias `@villuh/server/schemas/tags`, matching the established convention (`units/schemas.ts` → `@villuh/server/schemas/filters`). Resolves in both Node ESM (self-reference) and the client build.
- **Files modified:** `apps/server/src/modules/amenities/schemas.ts`
- **Verification:** `pnpm --filter @villuh/landlord-web build` exits 0; `pnpm turbo run lint typecheck` 12/12, 0 errors.
- **Committed in:** `8f9d4ce` (Task 1 commit)

**2. [Build ordering] Catalog dialog committed in Task 1, not Task 2**
- **Found during:** Task 1
- **Issue:** The plan assigns `ManageAmenityCatalogDialog` to Task 2, but `amenities.overlays.ts` (Task 1) references it via `flag(ManageAmenityCatalogDialog)`, so Task 1 cannot build without the file.
- **Fix:** Created the complete catalog dialog in Task 1 so the registry compiles; Task 2 then delivered the card + template replacement. No behavior change vs the plan — the file's Task 2 acceptance criteria still pass.
- **Files modified:** `apps/landlord-web/modules/amenities/components/manage-catalog-dialog.tsx`
- **Committed in:** `8f9d4ce` (Task 1 commit)

**3. [Scope trim] Photo count omitted from the amenity card**
- **Found during:** Task 2
- **Issue:** The plan mentions a photo count on the card, but `amenities.property.list` does not expose an image count and a per-card `gallery.list` would be an N+1.
- **Fix:** Card shows the icon tile, name, description snippet, and a Reservable badge (D-42 discretion); photo count omitted rather than adding N+1 queries or a new server field.
- **Files modified:** `apps/landlord-web/modules/amenities/components/amenity-card.tsx`
- **Committed in:** `7a3ecdc` (Task 2 commit)
