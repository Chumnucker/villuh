# Phase 03.3 Plan 09: Real Amenities on the Property About Tab Summary

The property About tab now renders real amenities (`amenities.property.list`) as a
read-only colored chip row via `AmenityChipRow`; grep proved the tags-as-amenities
stopgap never existed at this commit, so D-14 collapsed to adding the real feature only.

## What Was Built

- **`PropertyAmenitiesCard`** (inline in `property-about-template.tsx`): a
  self-sufficient card that reads `property.id` from `usePropertyDetail()` and queries
  `trpc.amenities.property.list({ propertyId })`, rendering the denormalized rows through
  `AmenityChipRow` (label/iconKey/colorKey → colored `TagBadge` chips, D-23).
- **Read-only by design** — no add/remove affordance; amenity editing lives in property
  settings (Plan 07). The card is hidden entirely when the property has no amenities
  (subtle empty state = render nothing), so the About tab stays clean.
- Mounted after `PropertyDetailsCard` in `PropertyAboutTemplate`.

## Task 1 Finding — Stopgap Does Not Exist (grep evidence)

Task 1 mandated confirming, by grep, whether any surface presents property **tags** AS
**amenities** before removing anything. It does not. Task 1 therefore collapsed to
case (b) in the plan ("D-14 collapses to add the real amenity chip row — Task 2 only"),
and made **no code change**.

Confirming grep (`rg -in "listPropertyTags|amenit" apps/landlord-web/modules/properties`
and `rg -n "PropertyBadgeRow" …`):

```
components/view/property-badge-row.tsx:19:  const { data } = trpc.tags.listPropertyTags.useQuery({
components/tags/manage-tags-dialog.tsx:68/77  (u) => u.tags.listPropertyTags
components/tags/tag-picker.tsx:123/138        trpc.tags.listPropertyTags
lib/property-tab-groups.ts:142-145            value/label "amenities"/"Amenities" → ROUTES.propertySettingsAmenities
templates/settings/property-settings-amenities-template.tsx  → placeholder "Amenities coming soon"
components/view/header.tsx:114                 <PropertyBadgeRow />
```

Evidence interpretation:
- `PropertyBadgeRow` (detail header, mounted at `header.tsx:114`) renders
  `tags.listPropertyTags` as **property TAGS** — its own docstring describes it as the
  property-type + tags summary, editing lives in settings. `property_tag` is a separate
  real feature (D-21), so this is **legitimate tag display, NOT an amenity stopgap**. Left
  untouched.
- Every other `listPropertyTags` match (`manage-tags-dialog`, `tag-picker`) is genuine tag
  management.
- Every `amenit` match was either the settings tab label/route or the
  `property-settings-amenities-template.tsx` **placeholder** — no surface rendered tags
  under an amenities label.

Per the Task 1 acceptance criterion, `rg -n "listPropertyTags" .../components/view` still
returns the `PropertyBadgeRow` match; this SUMMARY documents it as legitimate property-tag
display, not an amenity stand-in. The codebase now has exactly one representation of "this
property has amenities" — the real chip row added in Task 2.
