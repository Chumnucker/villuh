## Decisions Made
- **Cross-entity (D-36) via org filter.** The Plan-02 `update`/`remove` input schemas carry only `propertyAmenityId` (no `propertyId`), so the meaningful, testable "id from another property" rejection is a foreign-org caller — `requirePropertyAmenity`'s `organizationId` filter returns `NOT_FOUND`. `requirePropertyAmenity` still accepts an optional `expectedPropertyId` for callers that have one.
- **Duplicate catalog attach → BAD_REQUEST.** `property_amenity_catalog_unique` (23505) is mapped in a dedicated rethrow helper on `add` and `set`, mirroring the catalog/floor-plans precedent.
- **Description denormalized from catalog** on `add`/`set` (the column exists; a harmless superset of D-23's label/icon/color).
