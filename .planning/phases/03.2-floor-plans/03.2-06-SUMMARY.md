# Phase 03.2 Plan 06: Floor Plan Wizard Summary

Built the interactive heart of the floor-plans feature: the pure display helpers, the owner-agnostic staged-gallery retarget, and the `FloorPlanWizard` that composes 03.2-05's `WizardDialog` primitive around a single `@tanstack/react-form` instance + staged gallery for both create (`mode="linear"`, Details → Photos → Review) and edit (`mode="free"`, Details → Photos, no Review). An abandoned wizard is truly side-effect free — images stage in memory and persist only on Confirm/Save (D-41).

## What Was Built

**Task 1 — display helpers + staged-gallery retarget + copy props (`fdbaa49`)**
- `lib/floor-plan-display.ts` (pure, no React): `formatFloorPlanSpecs` (`2 bd · 1.75 ba · 1,100 sq ft`, `Studio · 1 ba · 480 sq ft`, `3 bd · 2 ba`), `formatBathrooms` (`String(Number(n))` trims `1.00`→`1`, `1.50`→`1.5`, keeps `1.75`), `formatUnitCount` (`No units assigned` / `1 unit` / `{n} units`), ` · ` (U+00B7) separator (D-39).
- `staged-gallery.ts`: dropped `propertyId` from `PersistDeps`/`persistStagedGallery` — owner-agnostic; callbacks close over the id (D-43).
- `staged-gallery-field.tsx`: optional `emptyTitle`/`emptyDescription` props defaulting to the property strings (Resolved #1) — property form byte-identical in behaviour.

**Task 2 — the three step panels (`18a78d7`)**
- `wizard/floor-plan-form.ts`: `FloorPlanFormValues`, `EMPTY_FLOOR_PLAN_VALUES`, `toFloorPlanFormValues`, `toCreateInput`/`toUpdateInput` boundary converters (D-07), `BEDROOM_OPTIONS` (0–10) + `BATHROOM_OPTIONS` (41 items, 0.25 steps, D-40/Resolved #4), `useFloorPlanFormInstance` + `FloorPlanFormApi`.
- `details-step.tsx` (§4.1): `grid gap-4 sm:grid-cols-2` child wrapper; Name (`sm:col-span-2`, placeholder `2 bed / 2 bath`, per-field `createFloorPlanInputSchema.shape.name`); Bedrooms select 0–10 (`0`→`Studio`); Bathrooms select 41 × 0.25 labelled via `formatBathrooms`; optional Default square footage with the `Optional. Units can override this.` hint.
- `gallery-step.tsx` (§4.2): `StagedGalleryField` reused unchanged with floor-plan empty copy; 25-cap left to `acceptImageFiles` (D-41a).
- `review-step.tsx` (§4.3): two bordered blocks reading live values via `useStore`; Block A Details (name, spec line, `IconBuildings` owning-property line), Block B Photos (cover + up to 6 thumbnails + `+{n}` + count copy); per-block ghost Edit calling `goTo`.

**Task 3 — FloorPlanWizard (`488e93d`)**
- Two independent `WizardDialog` roots (`CreateFloorPlanWizard`/`EditFloorPlanWizard`), switched on `overlay.value`.
- Create: `canAdvance` = Details valid; footer Back/Next then a `SubmitButton` (`Create floor plan`…); Confirm = `floorPlans.create` → `persistStagedGallery` (injecting `floorPlans.gallery.*` + `uploads.presignFloorPlanImage`) → invalidate `floorPlans.list`/`get` + `properties.get` (no org-quota, D-28/D-47).
- Edit: values from `floorPlans.get`, existing images seeded as `{ kind: "existing" }` from `gallery.list`, removals accumulate → hard-delete on Save; `SubmitButton` (`Save changes`…) + a dirty-only Discard; cold deep-link shows a skeleton, missing plan shows the not-found body + Close.
- `WizardRightColumn` owns the `<form>` (plan 05 contract) and the Enter-must-not-submit split; duplicate-name `BAD_REQUEST` maps onto the Name field + jumps to Details (D-09).

## Deviations from Plan

### Auto-fixed / adjusted

**1. [Rule 3 - Blocking] Retargeted `property-form.tsx` to the new `persistStagedGallery` signature**
- **Found during:** Task 1.
- **Issue:** D-43 removes `propertyId` from `persistStagedGallery`; `property-form.tsx` (the only existing caller) would then fail typecheck.
- **Fix:** Its `presign`/`add`/`remove`/`reorder` callbacks now inject `{ propertyId, ...input }`, closing over the owner id. Behaviour unchanged. Not in the plan's `files_modified`, but forced by the D-43 change.

**2. [Rule 3 - Blocking] Added `wizard/floor-plan-form.ts` (not in `files_modified`)**
- **Found during:** Task 2.
- **Issue:** The three panels reference the shared form API type + boundary converters, but must typecheck before the wizard (Task 3) exists — importing the type from the wizard would be a forward dependency that fails Task 2's `typecheck` gate.
- **Fix:** Extracted `FloorPlanFormValues`/converters/select options/`useFloorPlanFormInstance`/`FloorPlanFormApi` into a shared module, exactly mirroring the existing `property-form-shared.ts` pattern. `submitStatus`/`fieldError`/`UNSET` are still consumed from `property-form-shared.ts` per the plan (no reinvented constants).

**3. [Note] Duplicate-name error surfaced via a local `nameError` prop on `DetailsStep`**
- Rather than `form.setFieldMeta` (version-dependent field-meta shape), the wizard holds a `nameError` string and threads it into `DetailsStep`, cleared on the next Name edit. Fully typed and framework-version-independent while still rendering under the Name field via `FieldError` and jumping to Details (D-09).

**Total deviations:** 3 (2 blocking scope additions, 1 implementation-choice note). No application-logic deviations from the contract.
