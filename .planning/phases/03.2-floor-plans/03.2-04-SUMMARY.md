# Phase 03.2 Plan 04: Floor-Plans Integration Suite Summary

## Accomplishments
- **Task 1 (CRUD / uniqueness / number bathrooms / list shape):** create→read (D-05, D-23); `typeof read.bathrooms === 'number'` and `=== 1.75` (D-07); update mutates name/beds/baths/sqft; duplicate name in the same property → `BAD_REQUEST` (D-09) and the same name under a different property succeeds; `floorPlans.list` returns a numeric `unitCount` (=1 with an assigned unit) and `coverImageUrl` equal to the S3 mock's presigned URL (D-26); an archived plan is absent from the default list and present with `includeArchived: true` carrying `archivedAt` (D-26a).
- **Task 2 (rejection / immutability / archive / RLS / gallery):** cross-property assignment → `BAD_REQUEST` on **both** `units.create` and `units.update` (D-27); `units.update` carrying a foreign `propertyId` re-reads to the original property (D-27a); assigning a plan while leaving beds/baths/sqft unset keeps `unit.bedrooms/bathrooms/squareFootage` `null` (D-19); archiving an assigned plan leaves the unit's `floorPlanId` unchanged (D-11); the 26th image is refused by `uploads.presignFloorPlanImage` **and** `floorPlans.gallery.add` (D-14); the presigned `objectKey` never matches `^https?://` and contains `floor-plans/{planId}/gallery/`, round-tripping on `gallery.list` with a read-time presigned `url` (D-16); `gallery.remove` issues `DeleteObjectCommand` and removes the row (D-12); a second org reading/mutating the first org's plan or image gets `NOT_FOUND` (RLS, D-05/D-12).
- **Service fix (D-09):** `createFloorPlan`/`updateFloorPlan` `.catch(rethrowDuplicateNameAsBadRequest)` — unwraps drizzle's error wrapper and, on Postgres `23505` against `floor_plans_property_name_unique`, throws `badRequest(...)`.

### Auto-fixed Issues

**1. [Rule 2 - Missing critical functionality] D-09 duplicate-name rejection surfaced as INTERNAL_SERVER_ERROR, not BAD_REQUEST**
- **Found during:** Task 1 — the duplicate-name test (asserting `BAD_REQUEST` per the VALIDATION Automated Verification Map and D-09) failed with `INTERNAL_SERVER_ERROR`.
- **Issue:** Plan 02's `createFloorPlan` inserted directly; the `floor_plans_property_name_unique` violation (Postgres `23505`) bubbled up unmapped, so tRPC wrapped it as `INTERNAL_SERVER_ERROR`. The phase's D-09 contract requires `BAD_REQUEST`.
- **Fix:** Added `rethrowDuplicateNameAsBadRequest` and `.catch(...)` on the `createFloorPlan`/`updateFloorPlan` insert/update. It unwraps drizzle's error wrapper (code/constraint may live on the error or its `cause`) and throws `badRequest('A floor plan with that name already exists for this property.')` on a match; anything else is re-thrown unchanged.
