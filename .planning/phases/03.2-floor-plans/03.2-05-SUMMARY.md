# Phase 03.2 Plan 05: WizardDialog Primitive Summary

Built the reusable `WizardDialog` primitive in `@villuh/ui` — a general-purpose two-column wizard overlay that composes `dialog.tsx`'s public exports through `cn()` className merges (never editing `dialog.tsx`) plus a from-scratch vertical stepper drawn with `PlatformIcon` + Tailwind. The full D-30 surface (ten members incl. `WizardDialogPanel` and `useWizardDialog()`) is barrel-exported.

## What Was Built

**Task 1 — shell + hook (`feat(03.2-05)` `12c9f5d`)**
- `WizardDialog` root wraps `Dialog`, provides step context, owns uncontrolled step state seeded to `steps[0]`, accepts optional controlled `step`/`onStepChange`, tracks a `visited` set, and resets step + visited on close (D-33). `mode: "linear" | "free"` + `canAdvance` gate `next()` and forward reachability (D-34).
- `WizardDialogContainer` = `DialogContainer` + `cn("max-h-[85vh] sm:max-w-4xl flex-col sm:flex-row", …)` (D-31/D-32).
- `WizardDialogSidebar` uses the exact `flex shrink-0 flex-col gap-2.5 border-b bg-secondary px-4 py-4 pr-12 sm:w-64 sm:border-r sm:border-b-0 sm:pr-4` string (byte-identical `gap-2.5`/`py`/`bg-secondary` to `DialogHeader`) and auto-renders the mobile compact step line.
- `WizardDialogTitle`/`WizardDialogFooter` re-export `DialogTitle`/`DialogFooter`; `WizardDialogDescription` adds `hidden sm:block`; `WizardDialogBody` = `min-h-80 flex-1 overflow-y-auto px-6 pt-6 pb-6 sm:pt-12`; `WizardDialogPanel` toggles the `hidden` attribute, is `tabIndex={-1}`, and moves focus to itself on step change (skipped on initial mount).

**Task 2 — stepper + barrel (`feat(03.2-05)` `3d10459`)**
- `WizardDialogSteps`: `<nav aria-label="Wizard steps"><ol>` of `<li>` rows with an aria-hidden connector (`bg-primary` above a completed step, else `bg-border`, omitted on the last item) and a `<button type="button" aria-current disabled>` carrying the `size-6 rounded-full` badge, label, and `sr-only` state word (`Completed`/`Current step`/`Not started`). Renders all five §1.3 states; `IconCheckmark1` marks completed, Tailwind dots mark current/upcoming. Reachability follows `mode` (free = all; linear = visited ∪ immediate next when `canAdvance`).
- `export * from "./wizard-dialog"` added as the last line of `packages/ui/src/index.ts`.

## Deviations from Plan

None — plan executed exactly as written. No Rule 1–4 deviations were required.

One design decision left implicit by the plan was resolved conservatively: the plan's Task 1 action describes the wizard `<form onSubmit>` behavior, but D-30's fixed export list contains no `form` or `right-column` member and the consumer (`FloorPlanWizard`, plans 06/07) owns the `@tanstack/react-form` instance. The `<form>` element is therefore the consumer's; the primitive exposes `next()`/`isLast` via `useWizardDialog()` so the consumer's `onSubmit` implements the "Enter must not submit" contract. This keeps the primitive's boundary where the phase's other plans expect it.
