## Spacing Scale

Standard 8-point scale. All values are multiples of 4.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (`gap-1`) | Icon gaps, inline icon-to-text spacing |
| sm | 8px (`gap-2`, `p-2`) | Compact element spacing, helper text offset |
| md | 16px (`px-4`, `gap-4`) | Default field + form element spacing, card internal padding |
| lg | 24px (`px-6`, `gap-6`) | Card horizontal padding (established by Card component), section gaps |
| xl | 32px (`gap-8`) | Between form sections, between wizard step content blocks |
| 2xl | 48px (`py-12`) | Auth page vertical centering whitespace |
| 3xl | 64px (`py-16`) | Wizard full-screen vertical centering |

Custom spacing tokens already in globals.css:
- `--spacing-navbar: 4rem` (`h-navbar`) — top bar height
- `--spacing-page: var(--page-padding)` (`px-page`) — default `1rem`

Exceptions:
- Minimum touch target for icon-only buttons: 40px (`size-10`). All auth/wizard CTAs use labeled buttons so this applies only to icon-only action buttons (e.g. team table remove, dialog close).
- Auth pages use a centered column at `max-w-sm` (384px) — not a custom token, applied via class.
- Wizard progress bar: `h-2` (8px) — thinner than standard Progress component default of `h-3`.

Source: `packages/web/app/globals.css`, `packages/web/modules/common/ui/button.tsx`

## Typography

The codebase uses `--font-heading: var(--font-sans)` — Inter serves as both heading and body font. Gambetta Variable (`--font-mono`) is used for the Villuh wordmark only and must not be used in auth, wizard, or settings flows.

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 14px (`text-sm`) | 400 (regular) | 1.5 | Form labels, field descriptions, table cells, toast copy |
| Label | 14px (`text-sm`) | 500 (medium) | 1.4 | Field labels, nav items, button text, card description labels |
| Heading | 16px (`text-base`) | 500 (medium) | 1.2 | Card titles, dialog titles, wizard step headings, settings section headings |
| Display | 24px (`text-2xl`) | 500 (medium) | 1.1 | Auth page headline ("Create your account", "Welcome back"), wizard step number display |

Notes:
- `font-heading` class applies `--font-heading` (which maps to Inter). Use `font-heading font-medium` for card and dialog titles — matches established `CardTitle` and `DialogTitle` patterns.
- Auth page headlines use `text-2xl font-medium` — do NOT use `font-semibold` for Display role.
- `font-mono` is reserved for the `<h5 className="font-mono text-2xl font-medium">Villuh</h5>` wordmark in the sidebar. Do not use in auth/onboarding layouts.
- Two weights only: 400 (`font-normal`) and 500 (`font-medium`). Established by existing button and card components.

Source: `packages/web/app/layout.tsx`, `packages/web/modules/common/ui/card.tsx`, `packages/web/modules/common/ui/dialog.tsx`, CONVENTIONS.md

## Color

All color tokens are OKLCH CSS variables. Use semantic token names in Tailwind classes — never hardcode raw OKLCH values.

| Role | CSS Token | Light Value | Usage |
|------|-----------|-------------|-------|
| Dominant (60%) | `--background` | `oklch(1 0 0)` (white) | Auth page background, wizard page background, settings main area |
| Secondary (30%) | `--card` / `--sidebar` | `oklch(1 0 0)` / `oklch(0.985 0 0)` | Auth form card surface, wizard step card, settings sidebar, settings section cards |
| Accent (10%) | `--primary` | `oklch(0.21 0.006 285.885)` (near-black) | Primary CTA buttons ("Create account", "Sign in", "Start free trial", "Save changes") |
| Destructive | `--destructive` | `oklch(0.577 0.245 27.325)` (red) | Remove team member confirm button, disconnect integration confirm button |
| Muted text | `--muted-foreground` | `oklch(0.552 0.016 285.938)` | Helper text, placeholder text, secondary labels, disabled state copy |
| Ring / Focus | `--ring` | `oklch(0.705 0.015 286.067)` | All focus-visible ring outlines on interactive elements |
| Border | `--border` | `oklch(0.92 0.004 286.32)` | Input borders, card dividers, separator lines |

Accent (`--primary`) reserved for:
1. The single primary action button per page (form submit CTA)
2. The "Start free trial" button in wizard Step 4
3. The "Upgrade" CTA in the upgrade modal
4. Active plan tier highlight border in the pricing card grid

Dark mode: All listed tokens have dark counterparts already in `globals.css`. No new dark overrides needed for Phase 2.

Source: `packages/web/app/globals.css`

## Screens and Interaction Contracts

### Screen 1: Sign-up page `/register`

**Layout:** Centered auth card, max-w-sm, no sidebar, no navbar. Background: `bg-background`. Villuh wordmark above card using `font-mono`.

**Fields:** Name (Input, size default), Email (Input, type email), Password (PasswordInput — already exists in input.tsx with show/hide toggle).

**Actions:**
- Primary: `Button` variant `default` — "Create account" — full width (`w-full`), size `lg` (h-10)
- Secondary: Google OAuth — `Button` variant `outline` — "Continue with Google" — full width, size `lg`, leading icon via PlatformIcon

**Below form:** "Already have an account? [Sign in]" — `text-sm text-muted-foreground`, inline `LinkButton variant="link"`.

**States:**
- Loading: button disabled + spinner icon replacing icon slot
- Error (field): `aria-invalid` on Input, helper text below field via existing `Field` component
- Error (server): `toast.error()` via Sonner for network/auth failures

**Email verification intercept:** After successful registration, replace card content with a verification notice: heading "Check your email", body "We sent a verification link to {email}. Click it to activate your account." — no redirect, same page.

---

### Screen 2: Login page `/login`

**Layout:** Identical centered auth card layout to Sign-up.

**Fields:** Email (Input), Password (PasswordInput).

**Actions:**
- Primary: `Button` default — "Sign in" — full width, size `lg`
- Secondary: Google OAuth — `Button` outline — "Continue with Google" — full width, size `lg`
- Tertiary: "Forgot password?" — `LinkButton variant="link"` — right-aligned below password field

**Below form:** "Don't have an account? [Sign up]" — same pattern as Sign-up.

---

### Screen 3: Forgot password `/forgot-password`

**Layout:** Centered auth card, max-w-sm.

**Fields:** Email (Input, type email).

**Actions:** Primary: `Button` default — "Send reset link" — full width, size `lg`.

**Post-submit state:** Replace card content with: heading "Reset link sent", body "Check your inbox at {email}. The link expires in 1 hour." Back link: "← Back to sign in".

---

### Screen 4: Reset password `/reset-password?token=...`

**Layout:** Centered auth card, max-w-sm.

**Fields:** New password (PasswordInput), Confirm password (PasswordInput).

**Validation:** Client-side match check before submit — show `aria-invalid` on confirm field if mismatch.

**Actions:** Primary: `Button` default — "Set new password" — full width, size `lg`.

**Post-submit state:** Heading "Password updated", body "You can now sign in with your new password." + `LinkButton` → `/login`.

**Invalid/expired token:** Show error card: heading "Link expired", body "This reset link has expired or already been used. [Request a new one]."

---

### Screen 5: Team invitation accept `/accept-invitation/[id]`

**Layout:** Centered auth card, max-w-sm.

**Content:** Shows inviter name + org name. If invitee is not logged in: shows sign-up or sign-in form. If logged in: "You've been invited to join {org}. Role: {role}." + Accept and Decline buttons.

**Actions:**
- "Accept invitation" — `Button` default, full width, size `lg`
- "Decline" — `Button` variant `outline`, full width, size `lg`

### Screen 6: Onboarding wizard `/onboarding`

**Layout:** Full-screen, own layout group `app/(onboarding)/layout.tsx`. No sidebar, no navbar. Background: `bg-background`. Centered content column, max-w-md. Villuh wordmark top-left.

**Progress indicator:** Text label "Step {N} of 4" (`text-sm text-muted-foreground`) + `Progress` component (thin variant: `h-2`, full width) immediately below the wordmark row.

**Step container:** Single `Card` (default, `rounded-4xl`, `shadow-md`) centered vertically. Card uses existing `CardHeader` / `CardContent` / `CardFooter` pattern.

**Navigation:** "Back" — `Button` variant `outline`, size `default`. "Continue" / step-specific CTA — `Button` variant `default`, size `lg`. Both in `CardFooter`, justified end.

**Step 1 — Create property:**
- Heading: "Add your first property"
- Fields: Property name (Input, required), Street address (Input), City (Input), State/Province (Input), Postal code (Input)
- CTA: "Continue"
- On back from Step 2: prefills existing property data

**Step 2 — Add unit:**
- Heading: "Add your first unit"
- Fields: Unit label (Input, e.g. "Unit 1A"), Base rent (Input, type number, prefix "$")
- CTA: "Continue"
- Back: returns to Step 1 (property editable)

**Step 3 — Add tenant:**
- Heading: "Add your first tenant"
- Fields: Full name (Input), Email address (Input, type email)
- CTA: "Continue"
- Subtext: `text-sm text-muted-foreground` — "You'll send them an invite after setup is complete."

**Step 4 — Choose plan:**
- Heading: "Start your free trial"
- Sub-heading: `text-sm text-muted-foreground` — "30 days free. No credit card required. Full Pro access."
- Layout: 3 plan cards in a row (responsive: stack on mobile, row on sm+). Each card: tier name, unit limit, property limit, team limit, per-unit price. Pro card has `ring-2 ring-primary` to indicate it is pre-selected.
- Plan cards: use `Card` component, `size="sm"`. Selected state: `ring-2 ring-primary`. Unselected: default ring.
- Tier limits visible on each card per D-18: Starter (1–5 units, 1 property, 1 team member), Growth (6–20 units, 5 properties, 3 team members), Pro (21–50 units, unlimited properties, unlimited team members).
- CTA: "Start free trial" — `Button` default, size `lg`, full width — below plan cards
- Micro-copy: "Trial ends in 30 days. You can add a payment method in Settings at any time."

### Screen 7: Settings `/settings/*`

**Layout:** Two-column: fixed settings sidebar (left, `w-56 shrink-0`) + main content area (flex-1). Sidebar uses `bg-sidebar`, main content uses `bg-background`. This is within the main app layout (has top navbar).

**Settings sidebar nav items** (5 items, using existing `LinkButton variant="ghost-muted"` pattern with `justify-start gap-2`):
1. Account — `IconUser` icon
2. Team — `IconUsers` icon
3. Billing — `IconCreditCard` icon
4. Integrations — `IconPlug` icon (or `IconLink`)
5. Audit Log — `IconClipboard` icon

Active item: `Button variant="secondary"` (filled muted background) to distinguish from inactive ghost state.

**Settings / Account** (`/settings/account`):
- Sections: Profile (name, email — editable `Input` fields), Password change (current + new + confirm `PasswordInput` fields)
- Each section in a `Card` with `CardHeader` (title + description) + `CardContent` + `CardFooter` (save CTA)
- Save CTA: "Save changes" — `Button` default, size `default`

**Settings / Team** (`/settings/team`):
- Invite member: `Card` with email `Input` + role `Select` (Owner / Manager / Viewer) + "Send invite" `Button` default
- Member list: `Table` component — columns: Name, Email, Role (editable `Select` inline), Joined, Actions
- Remove member: `Button` variant `ghost-destructive` with `PlatformIcon` trash icon in Actions column. Confirm via `Dialog` — see Destructive Actions section.
- Role permissions editor: Below member table. Toggle grid per role per action category using `Switch` components. `Card` with `CardHeader` "Role Permissions" + `CardContent` grid.

**Settings / Billing** (`/settings/billing`):
- Usage summary: `Card` with progress bars (`Progress` component) for units used / limit, properties used / limit, team members used / limit. Values from `/api/me` response.
- Current plan: badge showing tier name (`Badge` component), status chip.
- Plan change: 3 plan cards (same pattern as wizard Step 4) — clicking a different tier triggers payment flow (SetupIntent → Stripe Elements `PaymentElement` embeds inline in a `Card` below plan grid).
- Stripe Elements container: `Card`, `CardContent` — `PaymentElement` mounted inside. Below it: "Save payment method & upgrade" — `Button` default.
- Invoice history: `Table` — columns: Date, Amount, Status (paid/open/void), Download link (`LinkButton variant="link"`)
- Payment method: current card display (`Card size="sm"`) + "Update payment method" `Button variant="outline"`.

**Settings / Integrations** (`/settings/integrations`):
- Two integration cards (`Card`, `size="sm"`): Stripe Connect + DocuSign.
- Each card: integration name + logo + connection status badge + CTA.
- Stripe Connect disconnected: "Connect Stripe Account" — `Button` default — triggers OAuth redirect.
- Stripe Connect connected: green "Connected" badge + "Disconnect" — `Button variant="ghost-destructive"` — confirm via Dialog.
- DocuSign disconnected: "Connect DocuSign" — `Button` default — triggers DocuSign OAuth.
- DocuSign connected: green "Connected" badge + "Disconnect" — `Button variant="ghost-destructive"` — confirm via Dialog.

**Settings / Audit Log** (`/settings/audit-log`):
- `Table` — columns: Timestamp, Action, Resource, Details (expandable).
- Pagination via existing `Pagination` component.
- Empty state: see Copywriting Contract.

### Persistent UI: Usage Warning Banner

Shown in-app when landlord is at 80%+ of any limit (units, properties, or members). D-45.

**Position:** Fixed below the top navbar, full width, z-index above main content. Dismiss button (X) on right.

**Visual:** `bg-amber-50 dark:bg-amber-950/30`, `border-b border-amber-200 dark:border-amber-800`, text `text-amber-900 dark:text-amber-200`. Height: 40px (equivalent to `h-10`).

**Copy:** "You're using {N} of {limit} {resource}. [Upgrade your plan]" — "Upgrade your plan" is a `LinkButton variant="link"` → `/settings/billing`.

---

### Persistent UI: Upgrade Modal

Shown when a 402 `PLAN_LIMIT` response is received from any Hono route. D-46.

**Container:** `Dialog` — existing component, `sm:max-w-md`.

**Content:**
- `DialogTitle`: "You've reached your {resource} limit"
- `DialogDescription`: current tier limits vs next tier limits in a side-by-side comparison layout (2 columns, `Card size="sm"` for each tier)
- Pricing shown per tier
- `DialogFooter`: "View billing plans" → `LinkButton` → `/settings/billing` (navigates and closes modal). "Maybe later" → `Button variant="outline"` → closes modal.

## Destructive Actions

| Action | Trigger | Confirmation Pattern |
|--------|---------|----------------------|
| Remove team member | "Remove" button in team table | `Dialog` — title + body + "Remove member" (`Button destructive`) + "Keep member" (`Button outline`) |
| Disconnect Stripe Connect | "Disconnect" button on integration card | `Dialog` — title + body warning about payment impact + "Disconnect" (`Button destructive`) + "Keep connected" (`Button outline`) |
| Disconnect DocuSign | "Disconnect" button on integration card | `Dialog` — title + body warning about signing impact + "Disconnect" (`Button destructive`) + "Stay connected" (`Button outline`) |

No destructive actions have a text-entry confirmation (e.g. type org name). Single-click confirm in Dialog is sufficient for these actions.

## Interaction States

All interactive elements must implement these states:

| State | Visual |
|-------|--------|
| Default | As described per component |
| Hover | `hover:` class already in component variants — no new rules needed |
| Focus-visible | `focus-visible:ring-3 focus-visible:ring-ring/35` — established in buttonVariants |
| Loading | `Button` disabled + left icon replaced with spinning `PlatformIcon` ("IconLoader" or equivalent at 16px). Text does not change (no "Loading…" replacement — avoids layout shift). |
| Disabled | `disabled:opacity-50 disabled:pointer-events-none` — established in buttonVariants and inputVariants |
| Error (field) | `aria-invalid` on Input triggers `aria-invalid:border-destructive/40` via inputVariants. Helper text via `Field` component in red. |
| Error (form) | `toast.error()` via Sonner for non-field errors (auth failures, network errors) |
| Success | `toast.success()` via Sonner for async operations (invite sent, settings saved, integration connected) |

## Layout Patterns

### Auth layout (`app/(auth)/layout.tsx`)
- Full-screen centered: `min-h-svh flex items-center justify-center bg-background`
- Inner column: `w-full max-w-sm px-4` (384px capped, 16px horizontal margin on small screens)
- Villuh wordmark above card: `font-mono text-2xl font-medium` (Gambetta), centered
- Card: standard `Card` component with `gap-6` internal spacing

### Onboarding wizard layout (`app/(onboarding)/layout.tsx`)
- Full-screen: `min-h-svh bg-background`
- Villuh wordmark + step counter: fixed top bar `h-16 flex items-center justify-between px-6 border-b`
- Step content: vertically centered `flex flex-1 items-center justify-center`
- Wizard card: `w-full max-w-md` (448px)
- No sidebar, no breadcrumbs, no `LayoutProvider`

### Settings layout (`app/(app)/settings/layout.tsx`)
- Two-column: `flex gap-0`
- Sidebar: `w-56 shrink-0 border-r bg-sidebar min-h-[calc(100vh-var(--spacing-navbar))]`
- Main: `flex-1 p-6`

### Usage warning banner
- Inserted as a sibling to the main content area, inside the main app layout, conditionally rendered when `unit_count / unit_limit >= 0.8 || property_count / property_limit >= 0.8 || member_count / member_limit >= 0.8`
- Uses amber tokens (outside the core OKLCH token set — acceptable one-off for warning semantics)
